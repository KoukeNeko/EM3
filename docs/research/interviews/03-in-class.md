### 任務 2：找「最新一週」的教材並打開 PDF

**第一個發現：根本沒有「週」。** 5 門課中有 4 門（演算法、網程、機率、HCI）整門課只有一個區段「一般」，所有東西按上傳時間往下堆。只有計算機系統管理有 `Week 1/2/3/5/6`（沒有 Week 4，名稱是老師手打的，跟實際週次無關）。

演算法概論的「最新教材」路徑：

| 步驟 | 動作                                                                    | 耗時                                            |
| ---- | ----------------------------------------------------------------------- | ----------------------------------------------- |
| 1    | 課程頁往下找到最後一個資料夾「06 Heap Sort」（y≈761，剛好在第一屏底緣） | —                                               |
| 2    | 點資料夾 → 進入資料夾頁，裡面**只有一個檔案**                           | 2.4 s（另一次網程 Ch. 7 資料夾花了 **18.7 s**） |
| 3    | 點 `06_HeapSort.pdf` → **強制下載**（6.5 MB）                           | 傳輸 0.7–1.4 s                                  |
| 4    | 去下載列／Finder 打開 PDF                                               | 視作業系統                                      |

- 課程頁 → 資料夾頁的檔案連結帶 `?forcedownload=1`，伺服器回 `Content-Disposition: attachment` → **一定是下載**。（`t3-01-folder-heapsort.png`）
- 同一個檔案**去掉 `forcedownload=1`**，伺服器回 `Content-Disposition: inline` → 瀏覽器內建 PDF 檢視器可直接預覽。也就是說「預覽」技術上完全可行，只是預設路徑把它關掉了。
- **隱藏的捷徑**：左側欄「內容 → 教材列表」（`local/courseextension/index.php`）把每個資料夾裡的 PDF 直接列成連結，而且**不帶 forcedownload** → 點了就是線上預覽。從課程頁算只要 2 次點擊。但這個入口名稱很普通，小雯從沒點過。（`t4-01-matlist-algo.png`、`t7-02-matlist-netprog.png`）
- 作業說明的附件（例如 `EX1_Spec.pdf`）同樣帶 `forcedownload=1`。
- 命名不一致：`0_Title`、`1_Introduction`、`02_GettingStarted`、`03_Growth of Functions`、`04 Divide and Conquer`、（沒有 05，位置被 `Exercise#1` 佔走）、`06 Heap Sort`。
- 「資料夾只裝一個檔案」是常態：演算法 6/6 個資料夾都只有 1 個 PDF；機率 10 個資料夾中有 2 個是 0 個檔案。每個資料夾都多一次換頁（約 2.4 s）。

> 「老師說『第三週』，可是頁面上只有 `03_Growth of Functions`。第三週是第三章嗎？還是第三次上課？我要自己換算。」「我下載資料夾裡已經有 `06_HeapSort (3).pdf` 了。每次點都多一份。」「原來『教材列表』可以直接看？那為什麼課程首頁不是這樣？」

_量測限制：headless Chromium 沒有內建 PDF 檢視器，「預覽 vs 下載」是以實際 HTTP 回應標頭判定，而不是用肉眼看渲染結果。_

結論：

- **沒有一門課用「課堂練習」這個詞來命名可繳交的東西。** 同一種東西叫 `Exercise#1`、`Assignment 1 On-Site Upload`、`HW 1`；「課堂練習」只出現在一個討論區名稱。

### 任務 6：上一頁、多分頁等習慣

- **上一頁很慢**：課程頁回應 `Cache-Control: no-store, no-cache…`，無法進 bfcache，按上一頁＝重新整頁載入（約 3.5 s）。好消息是捲動位置有還原（623 px → 623 px）。（`t7-01-after-back.png`）
- **延遲不穩**：同一類資料夾頁，多數 2.4 s，有一次 **18.7 s**。一般頁面 load 2.3–6.2 s，networkidle 3.6–9.2 s；課程頁 HTML 約 135 KB，每頁另外觸發 `core_courseformat_get_state`、`local_edwiserreports_get_plugin_config` 等 AJAX。
- **多分頁**：活動連結是一般 `<a>`，Cmd/中鍵點擊可正常開新分頁（✔）。但課程頁上的 PDF 連結帶 `forcedownload`，開新分頁只會觸發下載，不會出現可留著對照的分頁。
- 「全部收合」與區段收合會寫入使用者偏好（本次未點）；因此「臨時收起來看一下」其實會改到帳號狀態。
- 課程索引（左側欄下半部）把整份活動清單又列一次，在 1366 寬下與主內容重複，卻不會標示哪一項是新的或今天的。

> 「我在 VS Code 和 E3 間切來切去，按上一頁又要等三秒半，乾脆每次都開新分頁，最後開了二十個 E3 分頁。」

## 痛點排序（依課堂情境的嚴重度）

1. **PDF 一律強制下載。** 課程頁 → 資料夾 → `forcedownload=1`。伺服器其實支援 inline，「教材列表」頁也是 inline，只有預設路徑是下載。課堂上每換一份投影片就多一個下載檔。
2. **沒有「現在這堂課」，也沒有「這週」。** 4/5 門課是單一「一般」區段，最新內容永遠在最底下；課表時間只藏在課綱 iframe 裡。「第三週的練習」這句話在 E3 上無法直接對應。
3. **課堂練習無法辨識。** 名稱混亂（Exercise／Assignment／HW），模組全是 `assign`，唯一線索是 90 分鐘的開放窗；位置靠上傳順序，常在第二屏。
4. **繳交流程太長**：從課程頁到完成需 4–6 個動作，「儲存更改」在第一屏外；檔案挑選器有 Wikimedia、Google、伺服器檔案、作者、授權等雜訊；麵包屑誤寫「修改已繳交的作業」。
5. **頁面慢、上一頁不快取**：每次換頁 2–6 s，偶發 18 s；`no-store` 讓上一頁也要整頁重載。
6. **一個檔案也要包一層資料夾**：多一次換頁、多一層樹狀圖，命名編號不一致。
7. **焦點綜覽的課程清單難掃**：課號前綴、非學分課混在一起、不依課表排序；半螢幕時被空白頭像推下去。
8. **小螢幕／半螢幕不友善**：側欄固定佔 21% 寬，收合後浮動按鈕壓住內容。

## 對新 E3 客戶端的具體建議

### A. 「現在這堂課」偵測（課表驅動）

- 資料來源：課綱中的「上課時間/教室」代碼（`R34-EC114`、`T34R7-EC022`、`M567-ED117`…）。解析規則：星期字母 `M T W R F S U` + 節次（3 = 10:10–11:00、4 = 11:10–12:00、7 = 15:30–16:20、8 = 16:30–17:20…；節次表要做成可設定）＋教室。
- 首頁頂部固定一條 **Now bar**：「● 正在上課：演算法概論 · EC022 · 15:30–16:20（剩 32 分）」；課前 15 分鐘顯示「下一堂」，課後 30 分鐘內仍保留「剛下課」。點一下直接進入該課的「本堂課」視圖。
- 焦點綜覽的課程清單依「今天的課表順序」排序；非學分線上課收到「其他」群組；課名去掉 `【115上】515505` 前綴（課號改成次要灰字）。

### B. 課程頁：以「時間」重新組織，而不是照上傳順序

- 老師沒建週次時，**自動依日期分週**：用活動的新增／修改時間與學期第 1 週日期，推算「第 N 週」。這樣「第三週」就有意義，也不需要老師改課程結構。
- 頁面最上方是 **「本堂課」卡片**：本週新增的教材 + 開放時間與本堂課重疊的作業。其餘週次預設收合（收合狀態只存本機，不寫伺服器偏好）。
- **新的在上面**（或提供「新→舊」切換），並標示「NEW」與上傳日期。
- 單一檔案的資料夾**攤平**：直接顯示成 PDF 列（檔名 + 頁數／大小），省掉一次換頁。
- 窄版（≤ 700 px）設計：單欄、沒有固定側欄，課程內導覽改成頂部分頁（教材／作業／公告／成績）。

### C. 課堂練習的辨識與呈現

- 以啟發式判斷「課堂練習」：`assign` 的開放時間窗 ≤ 4 小時且與課表節次重疊，或名稱符合 `on-site|in-class|課堂|練習|lab|exercise`。
- 給它獨立的卡片樣式：倒數計時、可接受檔案類型（`.c` / `.zip`）、繳交狀態（未交／已交／遲交），並在 Now bar 上以徽章提示「本堂有 1 份要交」。
- 「回家作業」與「課堂練習」分開列，不再依名稱猜。

### D. PDF 快速預覽

- 所有 `pluginfile.php` 的教材連結**去掉 `forcedownload=1`**，在頁面內以側邊面板（pdf.js 或瀏覽器原生 viewer）開啟；1366 寬時左清單、右預覽，683 寬時全螢幕預覽 + 返回。
- 預覽面板提供「下載」「在新分頁開啟」「回到上次頁碼」。
- 大檔（例如 6.5 MB）先顯示第一頁，背景續傳；同一份檔案用 ETag 快取，不要每次重抓。

### E. 三步上傳

1. **拖放／選檔**：直接在作業卡片（課程頁或本堂課卡片）上，不必先進作業頁、再進編輯頁。
2. **確認**：顯示檔名、大小、是否符合可接受類型（不符合就當場擋下），以及「這會取代你先前的繳交」之類的提示。
3. **送出**：一顆固定在可視範圍內的「繳交」按鈕；完成後顯示回執（時間、檔名），而不是跳回長頁面。

- 預設只保留「上傳檔案」；Wikimedia、伺服器檔案、作者、授權欄位全部隱藏（授權在作業繳交情境沒有意義）。Google 雲端硬碟可放進「其他來源」。
- 麵包屑／標題依實際狀態顯示「繳交作業」或「修改繳交」。

### F. 速度與瀏覽器習慣

- 客戶端以 SPA + Web Service API 取資料（`core_course_get_contents` 等），換頁不重載整頁；上一頁由客戶端路由處理，即時返回並保留捲動位置。
- 所有項目都是真正的連結（可 Cmd/中鍵開新分頁），PDF 預覽也有獨立 URL。
- 預先載入「本堂課」需要的內容；顯示載入骨架，不要讓 18 秒的延遲看起來像當機。
