# 教師與助教訪談總結

2026-10-15 進行，訪談方式是模擬：10 個 agent 各自扮演一位教師或助教，用講師帳號在 E3 上觀察實際的教學頁面。觀察全程唯讀，所有非 GET 請求和會改偏好的網址都被攔下。受訪身分與引述都是模擬的，但 E3 的畫面、步驟數、載入時間和 API 行為都是實測的。

## 朋友提出的假設，驗證結果

> 「我想要可以在介面上新增、編輯各種教材：Markdown 編輯、新增不同的文件、建立小考、評分很重要——我最常用評分。我需要把大家的作業下載下來，改完再上傳回去。」

| 假設                 | 結果                                                                                                                                                                       |
| -------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 評分最常用           | **10 位全部同意**，是所有人的第一優先。不過每個人說的「評分」不一樣：助教要的是速度和批次，教授要看進度，寫作課要評語，設計課要看作品。                                    |
| 下載作業、改完再上傳 | **成立，但痛點不在按鈕。** E3 已經有「下載全部」和「上傳回饋 zip」，難的是資料夾用每份作業不同的「參與者編號」命名、對不回學號，CSV 編碼混亂，而且分數和回饋檔要分兩次送。 |
| Markdown 編輯        | 部分成立。想要的人用在公告、評語、小考題目，很少用在教材頁。不會 Markdown 的人需要按鈕列。                                                                                 |
| 新增文件／教材       | 需求低，而且 **E3 沒有開放建立或編輯教材的 API**。最多只能做「寫好複製、打開 E3 的表單貼上」。                                                                             |
| 建立小考             | 痛點在「打題目」，不在建立小考本身。手動建一份 10 題小考要約 24 頁、100 多次點擊；在外面產生 Moodle XML 再匯入題庫，約 7 頁就能完成。                                      |

## 觀察到的 E3 問題（教學端）

1. **繳交數字對不起來。** 期末報告在作業頁顯示 22 份已繳，評分表卻只有 18 份。有 4 份來自選課已失效的學生，不在評分表裡，照評分表改就會漏掉。
2. **學號接不起來。** 下載全部、離線評分工作表、回饋 zip 都用每份作業不同的「參與者編號」；API 的參與者清單也不給學號，只有成績簿的 gradable users 會給。
3. **評分表在 1366 到 1920 寬的螢幕上都要橫向捲動**，狀態欄窄到一字一行，第一個畫面連一列都放不下。單人評分畫面一打開就會寫入偏好設定。
4. **看不出學生看得到什麼。** 上傳教材預設立即公開；「強制下載」預設是勾選的，這也是學生抱怨 PDF 不能預覽的原因。公告也沒有預覽。
5. **有些設定錯了也沒有提醒。** 有作業沒有開任何繳交方式，學生根本交不了；截止時間設在 00:00；「全部評完才公布」藏在設定頁 4 個螢幕以下。
6. **刪除、隱藏、排序要先打開沒有標籤的「編輯模式」。** 「隱藏」在 E3 叫「暫存為草稿」。
7. **只提醒沒交的人做不到。** 自動提醒只在截止前有效，評分表篩選後也不能寄信。老師最後都是截圖貼到 LINE。
8. **表單很重。** 新增小考有 136 個欄位，一題選擇題有 42 個；上傳一個 PDF 有 18 個欄位，真正需要的只有 4 個。

## 整理後的需求，以及 EM3 怎麼做

| 優先 | 需求 | EM3 的做法 | API |
| --- | --- | --- | --- |
| 必要 | 一份正確的繳交與評分進度 | 課程「教學」分頁和首頁「待批改」卡片，用 submissions 加 grades 計算，連選課已失效但有交的學生也算進去 | `mod_assign_get_submissions`、`get_grades`、`list_participants` |
| 必要 | 快速逐份評分 | 評分工作台：左邊名單（顯示學號、篩選、搜尋），右邊是繳交內容、分數、評語、回饋檔；`J`/`K` 換人，`⌘↵` 存檔並跳下一位 | `mod_assign_save_grade` |
| 必要 | 學生沒有被漏掉 | 合併評分表和成績簿兩份名單，標示「選課已失效」「不在 E3 評分表」「旁聽」 | `core_grades_get_gradable_users` |
| 必要 | 下載 → 離線批改 → 送回 | zip 裡每位學生一個資料夾，命名為「學號_姓名_編號」，附成績表 CSV；把改好的 zip 拖回來，依資料夾自動對回學生，學生原本交的檔案自動略過 | `/webservice/upload.php`、`save_grade` |
| 必要 | 用試算表批次給分 | 匯入 CSV（認得學號、email、userid；UTF-8 或 Big5 都可以），寫入前先列出新舊分數對照，確認後才寫入 | `mod_assign_save_grades` |
| 應該 | 可重複使用的評語 | 評語片語庫，存在本機，可以匯出 | — |
| 應該 | Markdown 或按鈕排版的評語與公告 | Milkdown 編輯器，有固定按鈕列，也可以切到 Markdown 原始碼 | `mod_forum_add_discussion` |
| 應該 | 安心發公告 | 草稿自動保存，發布前預覽學生會看到的樣子，可以加附件、置頂 | 同上 |
| 應該 | 延長期限、提醒沒交的人 | 一鍵延長 +1、+3、+7 天，預設勾選沒交的人；「複製未繳名單」貼到 LINE | `mod_assign_save_user_extensions` |
| 應該 | 作業設定檢查 | 在教學分頁標出「沒開繳交方式」「00:00 截止」「沒有截止時間」 | 唯讀 |
| 可以 | 小考出題 | 題目編輯器，支援單選、複選、是非、簡答、數值、申論；可以從試算表貼上，匯出 Moodle XML，再帶著步驟說明交接到 E3 的題庫匯入頁 | 沒有 API，只能交接 |
| 可以 | 寫教材 | Markdown 寫作區，一鍵複製成 E3 編輯器可以貼的格式，並列出四種 E3 表單的連結 | 沒有 API，只能交接 |
| 可以 | 刪除、隱藏、排序 | 在教學分頁集中列出 E3 對應頁面的連結 | 沒有 API |

## 還沒做，或做不到的

- **全部評完才公布（marking workflow）、指定評分者：** 要先在 E3 的作業設定裡開啟。EM3 存分數時會原樣帶回目前的工作流程狀態，不會把它重設。
- **評分規準（rubric）、給分指引：** E3 沒有開放 `core_grading_*` 定義相關的 API，EM3 讀不到也寫不了。
- **寄 E3 站內信：** 沒有寄信的 API。EM3 可以讀信和標為未讀，回覆要開 E3。
- **群組作業整組給分：** 存分數時帶 `applytoall=1`，但測試課程沒有群組作業，所以沒有實測。
- **寫入流程只用攔截的方式測過參數格式。** 成績、評語、回饋檔、公告、延長期限的實際寫入，需要在測試作業上確認一次，尤其要確認「只上傳回饋檔時送 `grade=-1` 會保持未評分」。

## 研究過程對帳號的副作用

- 一位 agent 勾選了「快速評分」，這個 GET 請求會存成偏好設定（`assign_quickgrading`），已經改回 0。
- 評分表的「每頁列數」（`assign_perpage`）被改成「所有」，已經從 E3 介面改回 50，並用 API 確認過。
- 之後唯讀瀏覽器（`scripts/e3-browser.mjs`）也會攔下 `quickgrading`、`perpage`、`filter`、表格排序這類會存成偏好的參數。
- 兩位 agent 下載過一次「下載全部」的 zip，只記錄了資料夾的命名方式，檔案已經刪除。
