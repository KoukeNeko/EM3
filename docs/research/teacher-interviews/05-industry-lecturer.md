# 教師訪談 05：業界講師（短期密集微學分課）

2026-10-15。模擬訪談加上實際觀察。帳號是 course 23571（ICT 微學分「React 前端網頁開發入門」）的 `editingteacher`，全程唯讀：沒有儲存、評分、發文、刪除、隱藏或切換編輯模式。報告裡沒有任何學生姓名、學號、信箱、繳交內容或成績，學生一律寫成〈學生A〉這類代稱。截圖和下載只留在 scratchpad。

## 受訪者

**EM，28 歲，前端工程師兼 ICT 微學分講師。** 就是這門課的講師本人。

- 課程型態：一學期見面約 10 次，每次晚上 18:30–21:30，學員 26 人來自各系所（21 位 student、5 位 guest 角色）。成績是 Pass/Fail：30% 出席（簽到與課堂練習各半）、70% 期末專題，60% 以上就通過。
- E3 上只有 7 個模組：公告、問題兩個討論區；課程前問卷、Flexbox Froggy、期末報告三份作業；兩支超級影片，其中一支叫「所以我要怎麼刪除一個資源？」，目前是「暫存為草稿」（＝隱藏）。
- **真正的教學其實不在 E3。** 從他自己發的公告可以看到：簡報與教材放在 Notion，課堂練習交到他自己用 React 寫的 judge 平台（emjudge，會自動測試），即時問答用 Slido，討論用 Discord，報告順序用 Google 試算表，課前問卷用 Google 表單。E3 只負責三件事：發公告、收期末專題連結、登成績。
- 習慣：鍵盤操作、Markdown、凡事想要「一個畫面做完」。

## 訪談重點（受訪者口吻）

**課前**

> 「上課前我只會在 E3 做一件事：發公告。內容我都先在 Notion 用 Markdown 寫好，再貼進 E3 的編輯器。貼過去粗體、清單有時候會跑掉，我就再手動修。」

> 「教材我不會放 E3。我在 E3 新增一個資源要填一整頁表單，在 Notion 改個字按一下就好了，所以教材放 Notion，E3 只放一個連結。」

**課中**

> 「上課的時候我根本不會開 E3。練習交 judge，有問題問 Slido 或 Discord。E3 對上課中的我來說是零。」

> 「真的要在課堂上做隨堂小考的話我也不會用 E3 的試卷。光是設定頁就有十幾個區塊，題目還要另外一題一題建。我寧可在 judge 上開一題。」

**課後**

> 「課後最花時間的就是改期末專題。每個人交兩個連結，一個 GitHub、一個 Vercel。我要點開 repo 看 code、點開網站看作品，然後切回 E3 打分數和評語，再按下一位。重點是看作品，不是在 E3 裡面找按鈕。」

> 「我截止時間設 6/1 00:00，結果一堆人以為是 6/1 晚上，晚了 8 到 23 小時才交。E3 只寫『到期：2026年 06月 1日(週一) 00:00』，連我自己都覺得很容易看錯。」

**看到觀察結果後的反應**

> （看到 Flexbox Froggy 的設定）「蛤，這份作業沒有開任何繳交方式？所以學生根本沒辦法在 E3 上傳截圖……難怪 26 個人全部『未繳』。我那時候以為預設會有檔案上傳。」

> （看到評分表只有 18 份、摘要卻寫 22 份需要評分）「所以有 4 個人交了，但是我在評分畫面完全看不到？這個很可怕，我可能會漏改。」

> （關於那支影片）「標題是在自嘲啦。我那時候傳錯一支影片，在活動頁面翻了半天找不到刪除，最後只找到把它『暫存為草稿』。我一直以為『暫存為草稿』是『還沒發布』的意思，後來才知道它就是『隱藏』。」

**對 EM3 的期待**

> 「我希望打開 EM3 就看到『你有 18 份期末報告還沒改』，按下去就是一個一個看，左邊是學生的連結和網站預覽，右邊打分數和寫 Markdown 評語，按 J 下一位。改完一次全部送出。」

> 「新增教材、改設定這種一學期做幾次的事情，給我一個按鈕直接開到 E3 的正確頁面就好，不用在 EM3 重做一遍。但我不希望每次都要在 E3 裡面重新找路。」

## 觀察紀錄

所有時間都是在桌機（1440×900）上用唯讀瀏覽器量的。這個瀏覽器會擋掉某些批次 AJAX 請求，所以評分畫面（grader）的 JavaScript 沒辦法完整載入，那部分的時間是用其他頁面推估的，下面會標出來。

### 任務 1：短期密集課在 E3 上的實際使用

| 時間點   | 在 E3 做的事                                                           | 在 E3 以外做的事                   |
| -------- | ---------------------------------------------------------------------- | ---------------------------------- |
| 開課前   | 開課程前問卷（作業本身不收東西，只放 Google 表單連結）                 | Notion 建教材頁                    |
| 每次課前 | 發公告（7 則：上課地點、Slido、Discord、教材連結、練習平台、期末提醒） | Notion 更新簡報                    |
| 課中     | 幾乎不用                                                               | judge 收練習、Slido、Discord、簽到 |
| 課後     | 上傳非同步影片（超級影片）                                             | judge 自動批改練習，助教處理       |
| 期末     | 收期末專題連結、評分、成績                                             | Google 試算表排報告順序            |

觀察到的問題：

- **兩份作業的「繳交方式」都沒開**（`nosubmissions=1`，沒有線上文字也沒有檔案上傳）。作業管理頁顯示「0 個已繳／26 個未繳」。作業本身就是「去外部網站做」，但如果講師本來想收截圖，E3 完全不會提醒他「這份作業學生交不了東西」。
- **截止時間 `00:00` 造成大量遲交。** 期末報告的到期日是 6/1 00:00，寬限到 6/2 21:30。22 份繳交裡有 8 份是在截止後 8.5–22.7 小時內交的，評分表上全部顯示成「已繳交 過期 N 小時」。
- 7 則公告都是 HTML 格式（`messageformat=1`），內容裡有很多連結和清單，受訪者表示都是從 Notion 貼過來的。

### 任務 2：批改 18 份期末報告

**作業的實際型態：** 只開「線上文字」，沒開檔案上傳（任務說明寫「線上文字＋檔案」，但設定裡只有 `onlinetext`）。每份繳交都是 69–555 字元的 HTML，裡面有 2–8 個連結。22 份繳交全部都有 GitHub 連結，17 份有 Vercel 部署網址，1 份附 Canva 簡報，2 份用其他網域部署。所以批改等於「點兩個外部連結，看 code 和網站，再回來打分數」。

**路徑與點擊數（從課程頁開始）：**

| 步驟                                      | 點擊              | 載入時間                   | 備註                                                                        |
| ----------------------------------------- | ----------------- | -------------------------- | --------------------------------------------------------------------------- |
| 課程頁 → 期末報告                         | 1                 | 1.3 s                      | 作業頁顯示「已繳交 22／需要評分 22」                                        |
| → 「繳交概況」分頁                        | 1                 | 0.4 s（DOM）               | 14 欄的表格，寬 1638 px，**超過 1440 px 的視窗**                            |
| 找到「線上文字」欄                        | 水平捲動          | —                          | 這一欄從 x=1260 開始；前面是系所/姓名、帳號、電子郵件、狀態、成績、修改時間 |
| 點學生的 GitHub/Vercel 連結               | 每人 2            | 外部網站                   | 連結是 `target=_blank`，會開新分頁                                          |
| 打分數                                    | 每列 ⋮ → 「成績」 | 進 grader                  | 或者勾「快速評分」直接在表格裡輸入                                          |
| grader：分數＋評語 → 「儲存後顯示下一位」 | 每人 3–4          | 推估 2–4 s／人（未能實測） | 「通知學生」預設勾選；上方顯示「總共 26 位，此為第 5 位」                   |

**最嚴重的發現：有 4 份繳交在評分畫面裡看不到。** 作業頁的評閱摘要寫「已繳交 22、需要評分 22」，但「繳交概況」表格只有 26 列，其中只有 18 列是已繳交；grader 的使用者選單也是「總共 26 位」。用 API 對照：

- `mod_assign_list_participants`：26 人，18 人 `requiregrading=true`。
- `mod_assign_get_submissions`：22 份 `submitted`，其中 4 份屬於不在上面 26 人裡的 student 角色帳號。

推測這 4 位的選課狀態已經不是「有效」（例如退選或選課期間已過），E3 的評分表預設只顯示有效選課。講師如果只看評分表，會以為只有 18 份要改。

**「下載全部繳交的作業」：** 下載很快（0.2 s，10 KB），zip 叫 `ICT.〈數字〉-期末報告-〈數字〉.zip`，裡面是 22 個資料夾（包含那 4 份）。每個資料夾叫 `〈學號〉 〈系所〉 〈姓名〉_〈參與者編號〉_assignsubmission_onlinetext`，裡面只有一個 `onlinetext.html`。對連結型作業來說，下載下來的檔案沒有用：只是把兩個連結包成 22 個 HTML。檔案已立即刪除。

**時間估計（18 份）：**

| 項目                                                               | 每人     | 18 人                                             |
| ------------------------------------------------------------------ | -------- | ------------------------------------------------- |
| 真正在看 code 和網站                                               | 2–3 分鐘 | 36–54 分鐘                                        |
| E3 操作成本（找欄位、開分頁、切回、等 grader、打評語、儲存下一位） | 25–40 秒 | 8–12 分鐘                                         |
| 發現並處理看不到的 4 份                                            | —        | +10–15 分鐘（要先察覺數字對不上，再去找選課篩選） |
| **合計**                                                           |          | **約 55–80 分鐘**（22 份約 70–100 分鐘）          |

E3 操作成本約佔總時間的 15–20%。真正浪費的不是秒數，而是在三個分頁之間切換時的注意力：看完 Vercel 網站回到 E3，要重新找到這個學生在哪一列。

### 任務 3：刪除、隱藏、排序一個資源

**結論：在不開編輯模式的情況下，E3 沒有任何地方可以刪除超級影片，也沒有任何地方可以調整順序。**

逐一檢查過的地方：

| 位置 | 有刪除？ | 有隱藏？ | 有排序？ | 備註 |
| --- | --- | --- | --- | --- |
| 課程頁（非編輯模式） | ✗ | ✗ | ✗ | 每個活動的 `li.activity` 都沒有 action menu、沒有拖曳把手。唯一的下拉是「完成」 |
| 活動頁的次導覽（超級影片／設定／報告／更多） | ✗ | ✗ | ✗ | 「更多」裡只有 過濾、權限、日誌、備份、還原 |
| 活動「設定」（`modedit.php?update=`） | ✗ | ✓ | ✗ | 隱藏藏在收合的「共通設定」裡，叫「暫存為草稿」；表單底部只有 儲存並返回課程／儲存並顯示／取消 |
| 側欄「作業管理」 | ✓（只限作業） | ✗ | ✗ | 每份作業有 [檢視] [修改] [刪除]，刪除連結是 `/course/mod.php?sesskey=…&delete=<cmid>` |
| 側欄「教材管理」 | ✗ | ✗ | ✗ | 只列「課程講義／參考資料／…暫存」四個分類（只認資料夾），超級影片不在這裡 |
| 側欄「討論區管理」 | ✗ | ✗ | ✗ | 只能新增討論區、訂閱 |
| `mod/supervideo/index.php` | ✗ | ✗ | ✗ | 只是清單 |
| 頁首「編輯模式」開關 | — | — | — | 這是 POST 到 `/editmode.php` 的表單（帶 sesskey），開了之後課程頁每個活動才會出現 ⋮ 選單（移動、暫存為草稿、刪除…） |

**為什麼難：**

1. **入口在錯的地方。** 講師要處理「這支影片」，自然會先進影片頁面找，但活動頁的「更多」裡沒有刪除。刪除只存在於課程頁的編輯模式，而且這個開關在頁首右上角，看起來像是一個全站偏好設定。
2. **E3 自己的管理頁不一致。** 「作業管理」有刪除欄，「教材管理」沒有，超級影片則沒有任何管理頁。講師學會了作業的刪法，換成影片又找不到。
3. **用詞誤導。** E3 把 Moodle 的「隱藏」改叫「暫存為草稿」。講師找「隱藏」找不到，找到「暫存為草稿」時又以為那是「還沒發布」的意思。課程頁的灰色標籤也寫「暫存為草稿」。
4. **隱藏也要 5 步。** 活動 → 設定（整頁表單，DOM 0.3 s，但等全部 JS 載完要好幾秒）→ 展開「共通設定」→ 可見性選「暫存為草稿」→ 儲存並返回課程。
5. **刪除與排序（依 Moodle 4.5 的標準流程推估，因為不能開編輯模式所以沒有實測）：** 開編輯模式 → 找到活動 → ⋮ → 刪除 → 確認 → 關編輯模式，6 步；排序則是編輯模式下拖曳，或 ⋮ → 移動 → 選目標位置。

**可以給 EM3 參考的 hand-off 網址：**

- 隱藏：`/course/modedit.php?update=<cmid>`，但要提醒「展開『共通設定』→ 暫存為草稿」。
- 作業的刪除：`/local/courseextension/index.php?courseid=<id>&scope=assignment`（作業管理頁，有刪除欄）。
- 其他模組的刪除：依 Moodle `course/mod.php` 的原始碼，`/course/mod.php?delete=<cmid>`（不帶 sesskey、不帶 confirm）應該會顯示 E3 自己的確認頁，再由使用者按確認。**這一點這次沒有實測**（規則禁止開刪除連結），要先在測試課程驗證。
- 排序：沒有 GET 網址可用，只能開 `/course/view.php?id=<id>#module-<cmid>`，然後提示「打開右上角編輯模式，拖曳左邊的把手」。

### 任務 4：隨堂小考與 Markdown 筆記頁

| 表單 | 網址 | 欄位（全部／預設可見） | 頁高（展開後） | 區塊數 | 備註 |
| --- | --- | --- | --- | --- | --- |
| 新增試卷（quiz） | `modedit.php?add=quiz` | 136／78 | 4016 px | 15 | 存好之後還要到另一頁加題目 |
| 新增選擇題 | `question/bank/editquestion/question.php?qtype=multichoice` | 42／30 | 2968 px | 6 | 17 個文字編輯器（題幹、每個選項、每個回饋） |
| 新增「線上編輯文件」（page） | `modedit.php?add=page` | 26／16 | 2147 px | 6 | 必填只有名稱和內容 |
| 新增檔案（resource） | `modedit.php?add=resource` | 31／18 | 2058 px | 6 | 檔案挑選器 |
| 試題匯入 | `question/bank/importquestions/import.php` | 15 | 1309 px | 3 | 支援 GIFT、Moodle XML、Aiken、CSV、Blackboard、克漏字、填空 |

**隨堂 3 題選擇題小考的最短路徑**（推估）：試卷管理 → 新增試卷 → 填名稱與開放時間 → 儲存並顯示 → 編輯試題 → 新增 → 從題庫或新試題 → 選擇題 → 填題幹與 4 個選項（×3）→ 儲存。約 25–35 次點擊、6–8 次整頁載入，大概 10–15 分鐘。受訪者說他課堂上沒有這個時間，所以都用自己的 judge 或 Slido。

**Markdown：** 「線上編輯文件」的內容欄預設是 TinyMCE（所見即所得）。編輯器偏好頁（`/user/editor.php`）有 TinyMCE、Atto、純文字區域三種選擇。依 Moodle 的行為，要改成「純文字區域」才會出現文字格式下拉選單（裡面有 Markdown），而且這是**整個帳號**的設定，會影響所有編輯器。這次沒有改偏好，所以沒有實測。E3 的「線上編輯文件」也沒有 Markdown 預覽。

## 痛點（依嚴重度排序）

1. **評分畫面漏掉 4 份繳交**（嚴重）。摘要寫 22、表格和 grader 只列 18，講師可能漏改。
2. **刪除、隱藏、排序的入口藏在編輯模式裡，而且 E3 的管理頁彼此不一致**（嚴重）。超級影片完全沒有非編輯模式的刪除入口；「隱藏」被改名成「暫存為草稿」。
3. **作業設定沒有健檢**（高）。兩份作業沒開任何繳交方式、截止時間設在 00:00 造成 8 份遲交，E3 都不會警告。
4. **連結型作業的批改要在 3 個分頁之間切換**（高）。線上文字欄在 1440 px 視窗外，需要水平捲動；看完網站要回來重新找學生。
5. **建立小考的成本對短期課來說太高**（中）。136 個欄位、題目要另外一題一題建。
6. **沒有 Markdown**（中）。公告和頁面都只能用所見即所得，從 Notion 貼過來格式會跑掉。
7. **「下載全部繳交」對連結型作業沒有價值**（低）。只是 22 個裝著連結的 HTML。

## 需求

**Must**

- 待批改清單：每門課、每份作業還有幾份沒改，數字要和 `mod_assign_get_submissions` 一致，包含非有效選課的繳交，並標示出來。
- 連結型作業的評分工作台：連結直接可點、鍵盤切換學生、分數與評語在同一個畫面。
- 結構性操作（新增、刪除、隱藏、排序、改設定）一鍵開到 E3 的正確頁面，並附上一行操作提示。

**Should**

- 用 Markdown 發公告，送出前可預覽。
- Markdown 評語。
- 作業設定健檢：沒開繳交方式、`00:00` 截止、沒設 cutoff、說明裡沒有任何連結等。
- 遲交資訊直接寫在每份繳交旁邊（「晚 8.5 小時」）。

**Could**

- 從純文字或 Markdown 產生 GIFT 檔，然後開 E3 的試題匯入頁。
- 匯出成績 CSV、Pass/Fail 試算（30% 出席＋70% 期末）。
- 檔案型作業的回饋檔上傳（給其他課用；這門課用不到）。

| 假設 | 判定 | 理由 |
| --- | --- | --- |
| 「想要在介面上新增、編輯各種教材：Markdown 編輯」 | **部分同意** | 想要 Markdown 是真的，但對象是**公告和評語**，不是教材。他的教材全在 Notion。而且 API 沒辦法建立或編輯 page，所以「EM3 裡編輯教材頁」做不到，最多提供「Markdown → HTML 複製」再開 E3 表單。 |
| 「新增不同的文件」 | **不同意（對這位講師）** | 整學期只建了 7 個模組。新增的頻率很低，hand-off 到 E3 就可以接受。他真正卡住的是**刪除和隱藏**，不是新增。 |
| 「建立小考」 | **不同意（對這位講師）** | 課堂練習用他自己的 judge，即時問答用 Slido。E3 的試卷成本太高，他不會用。可以做 GIFT 產生器當作 Could。 |
| 「評分很重要，我最常用評分」 | **強烈同意** | 這是他在 E3 上唯一花大量時間的工作，而且 API 完全支援（`mod_assign_save_grade(s)`）。 |
| 「需要把作業下載下來，改完再上傳回去」 | **不適用（對這門課）** | 這門課交的是連結，下載下來只是 22 個 HTML。需要的是「在一個畫面看連結和預覽」，不是 zip。對檔案型作業的課（例如朋友那門），這個需求仍然成立。 |

## EM3 教師模式提案

### 什麼要留在 EM3、什麼可以一鍵回 E3

| 留在 EM3（高頻、API 可寫）                    | 一鍵回 E3（低頻、或沒有 API）                                         |
| --------------------------------------------- | --------------------------------------------------------------------- |
| 待批改清單與數量                              | 新增活動、教材、試卷（開 `modedit.php?add=…`）                        |
| 評分、評語、批次送出                          | 隱藏（開 `modedit.php?update=<cmid>`，提示「共通設定 → 暫存為草稿」） |
| 寬限延期（`mod_assign_save_user_extensions`） | 刪除（作業開作業管理頁；其他模組開確認頁，需先驗證）                  |
| 發公告（Markdown → HTML）                     | 排序（開課程頁並提示開編輯模式）                                      |
| 繳交狀態、遲交、未繳名單                      | 試題匯入（EM3 產生 GIFT 檔後開匯入頁）                                |
| 作業設定健檢（唯讀）                          | 修正作業設定（開 `modedit.php?update=<cmid>`）                        |

每個 hand-off 按鈕都要寫清楚「會在 E3 開新分頁」，而且附一行提示，例如「在『共通設定』把可見性改成『暫存為草稿』」，不要讓講師到了 E3 還要重新找路。

### 功能排名（依這位講師）

1. **評分工作台**（Must，API 可行）
   - 左邊：學生的線上文字，連結解析成卡片（GitHub repo、部署網址），部署網址可以用 iframe 預覽（大部分 Vercel 網站允許 iframe；不允許時改成「開新分頁」按鈕）；GitHub repo 用公開 API 顯示最後 commit 時間是不是在截止之前。
   - 右邊：分數欄、Markdown 評語（評語存成 HTML，或用 `format` = Markdown 送出）、常用評語片段、「通知學生」開關。
   - 鍵盤：`J`/`K` 上下一位、`G` 跳到分數、`⌘Enter` 儲存並下一位。
   - 可以先暫存在本地，最後用 `mod_assign_save_grades` 一次送出，送出前列出「將通知 N 位學生」。
   - 一定要包含不在有效選課裡的繳交，並標示「選課狀態非有效」。
   - 遲交時間寫在學生旁邊。
2. **老師版首頁「待批改」**（Must，API 可行）：各作業的待批改數、最近一則提問（問題討論區）。用 `mod_assign_get_submissions` 計算，不要只用 `list_participants`。
3. **一鍵回 E3 的深連結與操作提示**（Must，只是連結）：涵蓋新增、隱藏、刪除、排序、設定、題庫匯入、成績匯入。
4. **Markdown 公告**（Should，`mod_forum_add_discussion` 可行）：在 EM3 寫 Markdown、預覽、轉成 HTML 送出；可以選擇置頂和立即寄送。
5. **作業設定健檢**（Should，`mod_assign_get_assignments` 唯讀可行）：例如「這份作業沒有開任何繳交方式，學生無法繳交」「截止時間是 00:00，學生常看成當天晚上」。修正則 hand-off 到設定頁。
6. **成績匯出與 Pass/Fail 試算**（Could，讀取可行；寫回只能產 CSV 再開 E3 匯入頁）。
7. **GIFT 小考產生器**（Could，產生檔案後 hand-off 到匯入頁）。
8. **教材頁 Markdown 編輯**（Won't，沒有 API）：最多提供「Markdown → HTML 複製」加上開 E3 表單。

### 研究限制

- grader 的批次 AJAX 被唯讀瀏覽器擋下來（畫面出現「TypeError: Failed to fetch」），所以它的載入時間和「儲存後顯示下一位」的時間是推估的。
- 編輯模式不能開，所以 ⋮ 選單的內容、刪除與排序的步數，都是依 Moodle 4.5 的標準流程推估。
- 「4 份繳交看不到」的原因是推測（非有效選課）。確切原因需要看成員頁的選課狀態，這次沒有查個人資料。
