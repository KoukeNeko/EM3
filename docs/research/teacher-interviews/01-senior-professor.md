# 教師訪談 01：資深教授，大班必修，工作全交助教

2026-10-15 進行。訪談對象是模擬的人物；實際操作則用真實的 `editingteacher` 帳號，在 E3 課程 23571（26 位修課者、1 個區段）上以 1920×1080 視窗**唯讀**進行。用的工具是 `scripts/e3-browser.mjs`（除了登入以外，所有非 GET 請求都會被擋下）和 `scripts/e3-ws.py`（只允許讀取的 API）。整個過程沒有送出表單、沒有張貼、沒有評分，也沒有切換編輯模式；「尚未繳交」篩選器會寫入偏好設定，所以只讀了它的選單結構，沒有套用（見任務 5）。截圖都留在 scratchpad，沒有放進 repo。報告裡不出現任何學生姓名、學號、Email、繳交內容或成績數值。

| 項目         | 內容                                                          |
| ------------ | ------------------------------------------------------------- |
| 身分         | 陳教授，62 歲，資工系資深教授                                 |
| 課程         | 大一必修「演算法概論」，150 人，4 位助教                      |

## 訪談重點（人物語氣）

**每週的工作流程**

> 「我一週進 E3 大概兩三次。星期一發這週的公告，上課前一天把投影片 PDF 放上去，其他時間基本不碰。」

> 「作業從出題到改完都是助教的事。我只想知道兩件事：大家有沒有交，助教改到哪裡了。可是要知道這兩件事，我每次都要打電話問助教。」

> 「期末最麻煩。我要把成績匯出來對一遍，再交到學校的成績系統。E3 有兩個地方都叫『成績管理』，我每次都不確定哪一個才是對的。」

**交給助教之後會出什麼問題**

> 「有一年助教把某個作業的成績先公布了，學生跑來問，我才知道。我根本不知道 E3 上哪個選項會讓學生看到成績。」

> 「助教也會換人。新來的助教在我的課上按錯設定，我要花半天才查得出是哪裡改了。」

> 「我最在意的是『我現在看到的畫面，學生是不是也看得到』。E3 從來不會告訴我。」

**對新工具的態度**

> 「你如果要我學一個新系統，第一個畫面就要讓我看懂。按鈕要大，字要大，而且不要有任何會『自己生效』的東西。」

> 「我不需要它什麼都能做。能讓我安心地發公告、看誰沒交，就很夠了。」

## 實際操作紀錄

時間是 `page.goto` 到 `networkidle` 的總耗時，點擊數從課程首頁開始算。

### 任務 1：每週要用的入口

- 課程頁的左側選單有 **22 個項目**（課程資訊 4、內容管理 9、評量管理 2、工具管理 4，再加上分類標題）。教授每週會用到的只有 3 個：公告列表、教材管理、成績管理。
- 預設字級是 **15px**，側欄連結是 18.75px。以 125% 縮放模擬放大後，成績表右側的欄位會被推出畫面，要水平捲動才看得到（截圖 `38-grader-zoom125.png`）。
- 課程頁載入約 1.6–2.0 秒；第一次打開成績頁時會跳出導覽小視窗「簡單地尋找學生 Next (1/3)」，剛好蓋住搜尋框。

### 任務 2：發公告（只開表單，沒有張貼）

**有兩個入口，兩張表單長得不一樣：**

|                | 討論區「公告」→ 新增討論主題      | 側欄「公告列表」→ 新增公告                         |
| -------------- | --------------------------------- | -------------------------------------------------- |
| 網址           | `/mod/forum/post.php?forum=28034` | `/blocks/dcpc_news/news/news_post.php?forum=28034` |
| 點擊數         | 2（課程頁 → 公告 → 新增討論主題） | 2（公告列表 → 新增公告）                           |
| 載入           | 1.5 秒                            | 3.0 秒                                             |
| 可見欄位       | 19 個                             | 18 個                                              |
| 「置頂」的名稱 | 置頂                              | 設為重要公告                                       |
| 議題訂閱       | 有                                | 沒有                                               |

兩張表單寫入同一個 forum，教授不會知道它們其實是同一件事。

- **編輯器**：頁面載入的是 TinyMCE（含 WIRIS 數學外掛）。我們的瀏覽器擋掉了 AJAX 批次請求，所以截圖裡只剩純文字框；教授實際看到的應該是完整的工具列。他不會用 Markdown，平常是從 Word 複製貼上。
- **附件**：Moodle 的檔案挑選器，標示「最多附件：9」。上傳一個 PDF 至少要 4 次點擊（＋ → 上傳檔案 → 選擇檔案 → 上傳此檔案）。學生研究已經指出，挑選器裡的作者欄和授權選項很干擾人。
- **排程**：在「顯示的期間」勾選「啟用」後，日、月、年、時、分要分別用 **5 個下拉選單**選，年份從 1900 列到 2050。預設值是開表單當下的時間，不是整點。排程過的公告在列表上只標一個英文的「Timed」。
- **Email 通知**：只有一個「立即發送通知」勾選框，沒有任何說明。不勾的話會照 Moodle 的預設，等編輯期限過了才寄；勾了就馬上寄。教授問：「不勾是不會寄，還是晚點寄？」表單上找不到答案。
- **沒有預覽**，也沒有「學生會看到什麼樣子」的畫面。按鈕叫「張貼」，按下去就馬上公開，或在排程時間公開。

> 「這個『立即發送通知』，我不勾的話學生到底收不收得到信？我最怕的就是發了公告，結果學生說沒收到。」

### 任務 3：上傳講義 PDF（只開表單）

一樣有兩條路：

|                                      | 新增「整包教材檔案」（resource）                 | 教材管理 → 新增文件（folder）                     |
| ------------------------------------ | ------------------------------------------------ | ------------------------------------------------- |
| 網址                                 | `/course/modedit.php?add=resource…`              | `/course/modedit.php?add=folder&…&scope=document` |
| 欄位總數 / 預設可見 / 全部展開後可見 | 31 / 7 / 18                                      | 28 / 18 / 18                                      |
| 區塊                                 | 一般、外觀、共通設定、限制活動參與、活動完成條件 | 一般、內容、共通設定、限制活動參與、活動完成條件  |
| 必填                                 | 名稱、檔案                                       | 名稱                                              |
| 載入                                 | 1.6–2.0 秒                                       | 1.6 秒                                            |

**對教授真正重要的只有 4 個欄位**：名稱、檔案、是否先不讓學生看到（「暫存為草稿」），以及要不要通知學生（「發送內容更改的通知」）。其他欄位，像活動編號、強制使用的語言、限制活動參與、活動完成條件、彈出視窗寬高、顯示檔案類型，他一個都看不懂，也不需要。

觀察到的陷阱：

- **「暫存為草稿」預設是「不需暫存為草稿」**，也就是一儲存學生就看得到。這正是教授最怕的事，而且這個選項藏在「共通設定」區塊裡。
- 教材管理表單的「強制下載檔案」**預設是勾選的**，這就是學生研究裡「PDF 一律強制下載」的來源。
- 「發送內容更改的通知」預設不勾，所以上傳講義時學生不會收到通知。
- 「文件類型」（講義／參考資料）只出現在教材管理那條路上；從課程頁新增的 resource 沒有這個欄位。
- E3 把 resource 改名叫「整包教材檔案」，但它其實只能放一個檔案；真正能放多個檔案的是 folder，E3 卻叫它「教材」。

> 「我只是要放一個 PDF，為什麼要看到『限制活動參與』和『活動完成條件』？而且你說預設學生馬上就看得到？那我以前放的期末考解答……」

### 任務 4：成績總表與成績匯出

**兩個都叫「成績管理」的頁面：**

1. 側欄「成績管理」（`/local/courseextension/grade/index.php`，E3 自製）
   - 有 8 個分頁：總成績、個人成績、全班微調、個人微調、給分方式、匯出、配分方式、編輯成績。
   - 「總成績」**只有 4 個計算欄**：依配分計算後得分、全班微調後分數、個人微調分數、課程總分。看不到各作業的成績。
   - 這門課還沒設定配分，所以 4 欄全部是「-」。
   - 每頁 20 人；150 人的課要翻 8 頁。
   - 表格上方有一個勾號標記，文字是「:學籍系統取得之成績」，教授看不懂意思。
   - 「編輯成績」分頁的連結帶有 `sesskey`，點一下就會進入可以修改成績的模式。它跟其他唯讀分頁長得一模一樣。
2. Moodle 原生成績表（`/grade/report/grader/index.php`，麵包屑也寫「成績管理」）
   - 每個作業一欄，加上 3 個計算欄和課程總分，共 9 個成績欄，前面還有姓名、帳號、Email 3 欄。在 1920 寬的螢幕上，最右邊的「期末報告」欄被切掉一半。
   - 每一格都有「•••」選單（Cell actions），一不小心就會點到。
   - 影片模組（supervideo）也變成成績欄，教授看不懂「所以我要怎麼刪除一個資源？」為什麼會有分數。

**匯出**（`/grade/export/xls/index.php`；E3 自製的 `/local/courseextension/grade/export/xls/index.php` 內容相同）

- 第一層要勾選 9 個成績項目，全部預設勾選。
- 「匯出格式選項」區塊預設是收合的，展開後有：匯出時包含回饋內容、排除休學的使用者、成績匯出顯示類型（實得分數／百分比／文字）、小數位數。
- 標題中英混雜：「Export as Excel 試算表」。
- 「下載」按鈕固定在畫面最底部，這部分還算清楚。
- 教授能看懂「勾選要哪些欄位 → 下載」，但不知道「文字」指的是等第，也不知道「排除休學的使用者」該不該勾。

> 「哪一個才是學校要的總成績？我要的就是一張『學號、姓名、總分』的表，對了沒問題就交出去。」

### 任務 5：找出還沒交「期末報告」的人

E3 上的路徑：

1. 側欄「作業管理」（1 次點擊）：會寫「期末報告 22 個已繳 / 4 個未繳」，**但沒有名單**。
2. 點「檢視」（第 2 次）：評閱摘要寫「參與者 26、已繳交 22、需要評分 22」。
3. 點「繳交概況」分頁（第 3 次）：1.6–2.7 秒。表格 1638px 寬，「狀態」欄被擠成一個字寬的直排文字（「未／繳／交／已／經／超／過…」）。因為有「線上文字」欄，26 列的頁面高達 7868px。
4. 點「狀態」下拉選單（第 4 次），再選「尚未繳交」（第 5 次）。選項是 GET 網址 `&status=notsubmitted`。Moodle 會把這個篩選條件存成使用者偏好，下次開啟時表格**仍然維持篩選狀態**。為了不改到這個帳號的偏好設定，我沒有實際套用，下面的結果是從未篩選的表格逐列計算出來的。

**結果：數字對不起來。**

| 來源                               | 已繳                                | 未繳                          |
| ---------------------------------- | ----------------------------------- | ----------------------------- |
| 作業管理列表                       | 22                                  | 4                             |
| 作業檢視頁「評閱摘要」             | 22（參與者 26）                     | 沒有顯示                      |
| 繳交概況表格逐列計算               | **18**                              | **8**                         |
| API `mod_assign_list_participants` | **18**                              | **8**（6 位學生、2 位旁聽生） |
| API `mod_assign_get_submissions`   | 22 筆 submitted、5 筆 new，共 27 筆 |                               |

`get_submissions` 裡有 4 筆已繳的紀錄，使用者已經不在目前的參與者名單中，可能是退選或身分變動。E3 的摘要把這 4 筆也算成「已繳」，再用 26 去減，所以「未繳」少算了一半。

> 「它跟我說 4 個沒交，助教說 8 個。我該信誰？」

只靠 E3，教授要點 5 次、讀一張擠成直排字的表格，最後得到的數字還和摘要互相矛盾。

### 任務 6：見下方的「假設驗證」和「功能排序」兩節

## 痛點（依嚴重程度排序）

1. **看不出學生看得到什麼。**
   - 上傳教材預設立即公開（「不需暫存為草稿」）。
   - 公告沒有預覽。
   - 成績表看不出哪些成績已經對學生公開。
   - 這是教授最主要的恐懼，E3 卻沒有任何「學生視角」的提示；側欄的「模擬角色介面」他不知道是做什麼的。
2. **繳交統計互相矛盾**（4 對 8），而且要點 5 次才看得到名單。
3. **兩個「成績管理」、兩個發公告的入口、兩種上傳教材的方式。** 名稱相同但內容不同，「編輯成績」和唯讀分頁長得一樣。
4. **字小、表格太寬。** 預設 15px；放大到 125% 後成績表要水平捲動；繳交表的狀態欄被擠成直排。
5. **Email 通知的規則看不懂。** 只有「立即發送通知」一個勾選框，教授無從得知不勾會發生什麼事。
6. **表單太長。** 上傳一個 PDF 要面對 18 個可見欄位，真正需要的只有 4 個。
7. **排程要選 5 個下拉選單**，年份從 1900 開始。
8. **150 人要翻 8 頁**（每頁 20 人），而且第一次打開會跳出導覽小視窗擋住畫面。

## 需求

**Must**

- 一個「學生會看到什麼」的明確提示：每則公告、每個檔案、每項成績都標示「學生可見／隱藏」。
- 每份作業的繳交進度：已交、未交、遲交、已改、未改，**數字要和名單一致**，並且分開學生和旁聽生。
- 一份未繳名單，可以複製下來轉給助教。
- 大字級（至少 18px），版面在 125% 縮放下不會水平溢出。
- 唯讀的成績總表：一頁看完全班，沒有任何可以編輯的元素。

**Should**

- 發公告的表單只保留標題、內容、附件和「是否寄 Email」，並說清楚寄信的時間點；送出前先預覽。
- 期末匯出「學號、姓名、各項、總分」一張表，欄位固定，不必勾 9 個選項。
- 看得到助教批改進度：哪份作業改到第幾份。

**Could**

- 上傳講義的精簡流程：名稱、檔案、預設先隱藏。
- 公告排程用「下週一早上 8 點」這種自然的選法。

## 對朋友假設的判定（以這位教授的角度）

| 假設                   | 判定                       | 說明                                                                                                                                        |
| ---------------------- | -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| Markdown 編輯          | **對他無用**               | 他從 Word 貼上，不知道什麼是 Markdown。這比較是年輕助教的需求。而且 API 無法建立或編輯 page。                                               |
| 新增不同的文件         | **部分成立**               | 他只需要「上傳一個 PDF」這一種，不需要各種模組。API 也無法建立 resource 或 folder，只能把人導到 E3 的表單，或改用「公告附件」這個替代做法。 |
| 建立小考               | **不成立**                 | 小考由助教出，他自己用紙本考試。                                                                                                            |
| 評分很重要、最常用評分 | **對助教成立，對他不成立** | 他從來不評分，只想「看」評分進度。對他來說重要的是唯讀的進度和成績總表，不是評分介面。                                                      |
| 下載作業、改完上傳     | **對助教成立，與他無關**   | 這是 4 位助教的工作流程，E3 已經有「下載全部繳交的作業」。他在意的是助教改完之後，成績有沒有被誤公開。                                      |

結論：朋友的假設描述的是**助教**的需求。對資深教授來說，最有價值的是「**安心地看**」（唯讀進度、未繳名單、成績總表、學生可見性），其次是「**安心地發**」（公告），而不是編輯和評分。

## 功能排序（給這位教授）

1. 繳交進度與未繳名單（唯讀）
2. 唯讀成績總表，標示學生可見性
3. 安全的公告發布：預覽、明確的寄信說明、大字
4. 期末成績匯出：固定欄位的 CSV／XLSX
5. 助教批改進度
6. 上傳講義的導引（交給 E3 處理）
7. 下載／上傳批改、評分介面（對他無用，但對他的助教有用）
8. 建立小考、Markdown 編輯（對他無用）

## EM3 功能提案與 API 可行性

### 1. 作業的「繳交進度」面板

**畫面**：在課程的作業分頁，每份作業顯示一條進度條（已交／未交／遲交／需評分）。點進去是未繳名單，學生和旁聽生分開，提供「複製名單」和「匯出 CSV」。

**API**（只讀）：

- `mod_assign_list_participants`（`submitted`、`requiregrading`、`grantedextension`、`roles`）
- `mod_assign_get_submissions`
- 兩者在 E3 上都已實測可用。

**注意事項**：

- 以 `list_participants` 為準，**不要用 submissions 的筆數去減**，否則會跟 E3 一樣把已退選者算進「已繳」。
- `roles[].name` 回傳的是未處理的 `{mlang zh_tw}旁聽生{mlang}{mlang en}Guest{mlang}`，客戶端要自己解析。

### 2. 唯讀成績總表

**畫面**：一頁看完全班，大字，可以凍結欄位；每一格標示「學生可見／隱藏」；沒有任何編輯元素。

**API**：

- `gradereport_user_get_grade_items courseid=23571` 會一次回傳全班 26 人的所有成績項目，並帶 `gradeishidden`、`gradehiddenbydate`、`gradeislocked` 等欄位，已實測。
- `gradereport_grader_get_users_in_report`、`core_grades_get_gradeitems` 也在 E3 的 mobile 服務清單中。

**注意事項**：supervideo 這類模組也會出現在成績項目裡，要能夠隱藏這一欄。

### 3. 期末成績匯出

**畫面**：用第 2 項的資料在客戶端產生 CSV／XLSX，固定欄位為學號、姓名、各項成績、總分。

**API**：沒有額外需求。可以另外放一個「在 E3 匯出」的連結，直接打開 `/grade/export/xls/index.php?id=…`。

### 4. 發公告

**畫面**：

- 精簡表單：標題、內容（富文字或純文字）、附件。
- 「是否寄 Email」用白話說明寄信的時間點。
- 送出前先預覽，並顯示「這則公告會出現在 150 位學生的公告列表」。

**API**：

- `mod_forum_add_discussion`，附件先經由 `/webservice/upload.php` 上傳成 draft itemid。
- 依 Moodle 4.5 原始碼，options 只有 `discussionsubscribe`、`discussionpinned`、`inlineattachmentsid`、`attachmentsid` 四項，**沒有排程（timestart/timeend）和 mailnow**（需要在 E3 上驗證）。
- 因此要排程或立即寄信，只能導到 E3 的 `/mod/forum/post.php?forum=…`。
- EM3 是純前端，沒有伺服器，無法替使用者代為定時發送。

### 5. 學生可見性提示

**做法**：

- 教材：從 `core_course_get_contents` 的 `visible`、`uservisible` 判斷。
- 公告：看是否設定了 `timestart`。
- 成績：用 `gradeishidden` 判斷。
- 統一顯示成「學生看得到／看不到」的標籤。

這是唯讀功能，完全可行。

### 6. 上傳講義的導引

**限制**：沒有 API 可以建立 resource 或 folder。

**做法**：

- 提供一個按鈕，直接打開 E3 的「教材管理 → 新增文件」頁面。
- 旁邊附上「只需要填這 4 格」的檢查清單，並提醒「暫存為草稿」預設是立即公開、「強制下載檔案」預設是勾選。

**替代方案**：用第 4 項發一則附上 PDF 的公告。這樣可行，但教材會分散在公告裡，只適合當作臨時方案。

### 7. 助教批改進度

**API**：

- `mod_assign_get_grades` 的 `grader` 欄位可以統計每位助教改了幾份。
- `mod_assign_get_submissions` 的 `gradingstatus` 可以算出還沒改的數量。

這兩支都是只讀 API。

### 8. 提醒未繳學生（可選）

**API**：

- E3 的 mobile 服務清單中有 `core_message_send_instant_messages`。這是 Moodle 站內訊息，**不是** E3 的「我的郵件」（dcpcmail）。
- 這個 API 沒有實測過寄送；而且一旦誤用，影響範圍很大。

**做法**：先只提供「複製未繳名單和 Email」，讓助教自己去寄。

## 附註

- 研究過程中被擋下的請求都是頁面本身的 AJAX 或檔案挑選器的列表請求，沒有任何寫入成功。
- 篩選繳交狀態會寫入使用者偏好，所以沒有套用。
