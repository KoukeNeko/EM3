# 07 · 數學系助教：手寫作業的批改與回傳

2026-10-15 進行的模擬訪談與觀察。觀察用的是 `editingteacher` 身分在課程 23571（ICT 微學分 React 前端，26 位學生）上的唯讀瀏覽器（`scripts/e3-browser.mjs`）和唯讀 API（`scripts/e3-ws.py`）。全程沒有儲存、評分、上傳或修改設定。「下載全部繳交的作業」的 zip 只拿來分析資料夾命名規則，分析完就刪除了。

> 限制：這門課的作業都沒有開「上傳檔案」（期末報告只有線上文字），課程 23502 也沒有作業。所以學生交手寫 PDF 或照片的情況、批註 PDF（editpdf）的實際畫面，都沒辦法在 E3 上實測。另外，單一評分頁（grader）一打開就會 `POST /r.php/api/rest/v2/user/current/preferences`，這個請求被唯讀瀏覽器擋下來之後，頁面只剩一個「TypeError: Failed to fetch」對話框，兩個面板都一直在轉圈。報告裡凡是跟 grader 或 editpdf 有關、但沒有實測的地方，都標成「Moodle 4.5 上游行為，未在 E3 實測」。

## 受訪者

**阿哲學姊**，27 歲，應用數學系博士生，「微積分甲」助教，負責兩個班共 120 人。

- 學生交的是手寫作業掃描成的 PDF，常常是手機拍照：方向歪、一個人交好幾張圖、偶爾是 HEIC。
- 用 iPad + Apple Pencil 在 GoodNotes 批註，改完要傳回去給學生。
- 依題給分：每題 0–5 分，最後加總。
- 筆電只在「搬檔案」和「打分數」的時候用。

## 訪談重點

**每週流程**

> 「作業是週三 23:59 截止，我週四晚上開始改，週日改完，週二上課前要回傳。兩個班 120 份，一週大概花 10 到 12 個小時，其中**真的在看數學的時間大概只有一半**。」

> 「流程是這樣：筆電上 E3 → 兩個班各下載一次 zip → 解壓縮 → 打開每個資料夾，把手機照片轉正、合成一份 PDF → 丟到 iCloud → iPad 的 GoodNotes 匯入 → 改 → 匯出 → 回到筆電 → 一份一份上傳回去，或者把檔案塞回原本的資料夾重新壓縮上傳 → 再把 120 個分數打進 E3。」

**iPad 和筆電的分工**

> 「我想全部在 iPad 上做完，可是 E3 在 iPad 上很難用：左邊選單佔掉三分之一個螢幕，表格往右滑才看得到分數欄。所以 iPad 只拿來批改，下載、整理、上傳和打分數全部在筆電上做。檔案在兩台機器之間來回傳兩次，每一次都有機會搞丟或放錯。」

**每一份要花多少時間**

> 「看一份大概 3 到 4 分鐘。整理檔案（轉正、合併、改檔名）每份大概 1 分鐘，上傳加打分數又要 1 分鐘。120 份光雜事就要 4 個小時。」

**最痛的地方**

> 「檔案格式亂七八糟：有人交 PDF，有人交五張 JPG，有人交 HEIC，還有人把照片貼進 Word。GoodNotes 匯入一整個資料夾的時候，每張圖都會變成一份獨立的文件，120 個人就變成 300 多份文件。」

> 「改完的檔案對不回學生。GoodNotes 匯出的時候用的是文件名稱，如果我在 iPad 上改過名字，或者那份是我自己合併出來的，檔名就跟 E3 那串『學號 系所 名字_一串數字_assignsubmission_file』對不上了。zip 上傳是成功了，可是有幾個人沒收到，我也不知道是哪幾個。」

> 「分數要打兩次：先在 GoodNotes 的頁面上寫每題幾分，再到 E3 打總分。我其實想要每題的分數都留著，學生問『第三題為什麼 2 分』的時候才查得到。」

**對 E3 內建批註 PDF 的看法**（看了截圖和上游文件之後）

> 「網頁上的筆跟 Apple Pencil 差很多，沒有壓感，手掌也會誤觸。而且它一次只開一個學生，每換一個人都要等它轉檔。我不會放棄 GoodNotes。我要的是**檔案進出不用我管**。」

### 任務 2：E3 的批註 PDF（editpdf）

- 從 API 看到三份作業都有開 `assignfeedback editpdf enabled=1`、`assignfeedback file enabled=1` 和 `assignfeedback comments`，表格裡也有「批註的PDF檔」欄位。可是**沒有一份作業開了檔案繳交**，所以這門課的批註 PDF 根本沒有東西可以批註。
- 設定頁的「給評設定」有四種：評語回饋、批註的PDF檔、**離線計分試算表**（有這個選項，但這三份作業都沒開）、回饋檔案。
- **上游行為（Moodle 4.5，未在 E3 實測）**：
  - editpdf 會把一位學生的所有繳交檔案合併成一份 PDF，在網頁上用筆、螢光筆、印章、文字框批註，產出一份「批註的PDF檔」。
  - 非 PDF 的檔案（Word、圖片）要伺服器有開文件轉換器才能批註，E3 有沒有開無法確認。
  - 可以手動把頁面轉 90 度，但不會自動校正手機照片的歪斜。
  - 一次只能處理一位學生，換人時要重新合併、轉檔。
  - 批註的結果只能在 E3 網頁上產生，**沒辦法用 zip 匯入**。

### 任務 3：下載 → 批註 → 上傳回饋 zip

**下載**：動作 → 下載全部繳交的作業，1 次點擊。下載是直接的 GET，不到 0.1 秒。

- zip 檔名是 `〈課程簡稱〉-〈作業名稱〉-〈cmid〉.zip`，例如 `ICT.20260316-期末報告-218500.zip`。
- 22 位已繳交的學生各一個資料夾，總共 22 個檔案，解壓後約 6 KB（因為都是線上文字）。
- 資料夾名稱（勾選「以分開的資料夾方式下載」時）：

  ```
  〈學號〉 〈系所〉  〈系所英文縮寫〉 〈姓名〉_〈參與者編號〉_assignsubmission_onlinetext/onlinetext.html
  ```

  - 全名部分就是 E3 顯示的「系所 / 縮寫 姓名」加上學號。`/` 被拿掉了，所以中間會留下兩個空格。
  - 〈參與者編號〉是 7 位數。我拿它跟 `mod_assign_get_user_mappings` 比對，22 個裡有 22 個相符。**它不是 userid，也不是學號**，每份作業各有一套。
  - 檔案繳交的資料夾會是 `…_assignsubmission_file/〈學生原始檔名〉`。

**上傳回饋 zip**：動作 → 以一個壓縮檔上傳多個回饋檔案，頁面 1.6–2.2 秒。頁面上只有一個檔案選擇器（只接受 `.zip`）和「匯入回饋檔案」按鈕。**命名規則只寫在「?」說明泡泡裡**：

> 「指派給學生的回饋檔，其檔名的構成是使用者完整姓名加上識別編號。……沒有變更的檔案將被忽略。」

依 Moodle 上游的 `importziplib` 規則（未實際上傳驗證），檔名要怎麼取才對得回學生：

1. 每一層路徑都會用 `_` 切成最多 5 段：`〈全名〉_〈參與者編號〉_〈plugin 類型〉_〈plugin 名稱〉[_〈檔名〉]`。
2. **真正用來比對學生的是第 2 段的參與者編號**。全名裡如果有 `_` 就會切錯，所以下載時 E3 已經把 `_` 換成空格。
3. 第 3、4 段必須是有效的 plugin，例如 `assignsubmission_file`。整段被改掉的話，這個檔案會被**默默略過**。
4. 資料夾模式下，資料夾名稱必須原樣保留，裡面的檔名可以隨便取；非資料夾模式下，檔名本身必須是 `全名_編號_assignsubmission_file_原檔名`。
5. 跟原本繳交的檔案**同名而且內容沒變**的檔案會被忽略；同一位學生的回饋檔案如果同名，會被覆蓋。
6. 以 `.` 或 `~` 開頭的隱藏檔會被忽略（macOS 的 `__MACOSX/._*` 不會出問題）。
7. 匯入的檔案會放進「回饋檔案」，**不會變成「批註的PDF檔」，也不會帶分數**。
8. 匯入前會有一頁確認清單，列出每個檔案對應到哪位學生。

學姊的流程會在第 3、4 點出錯：GoodNotes 匯出時用的是文件名稱。她如果把多張照片合併成一份新的 PDF，再改名成好讀的「〈學號〉 〈姓名〉.pdf」，參與者編號就不見了，這個檔案就會被略過。

**分數**：zip 不會帶分數。有三條路可以把分數放進 E3：

- 在 grader 一位一位打。
- 在繳交概況打開「快速評分」，在表格裡打。
- 去成績簿用「匯入 CSV」。這是課程層級的功能，要對應欄位、選編碼（UTF-8/CP950/BIG5 等幾十種）、預覽。

離線計分試算表雖然有這個選項，但要先改作業設定才能用。

**粗估每週點擊數**（兩個班、120 份、每份 1 個回饋檔）：

| 做法            | 點擊數                                                                                                                                 |
| --------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| grader 逐一處理 | 打開檔案挑選器 → 上傳 → 選檔 → 確認 → 打分數 → 儲存後顯示下一位，每人約 7 次 × 120 ≈ **840 次**                                        |
| zip + 快速評分  | 下載 2 次＋上傳 zip 約 6 次＋開快速評分、打 120 個分數、儲存。點擊少，但**檔案對應出錯時不會有任何提示**，只能看確認清單一筆一筆核對。 |

### 任務 4：依題給分

- 設定頁的「評分方式」有三種：**直接評分**（目前用這個）、**給分指引**（marking guide）、**評分規準**（rubric）。進階評分頁顯示「改變啟用的評分方式為 給分指引 / 評分規準 / 直接評分」。我沒有切換，因為切換會寫入。
- **給分指引**最接近學姊要的：每一題是一個「準則」，各自設定滿分（例如 5 分），每題可以寫評語，總分自動加總後寫進成績。
- 問題：
  - 學期中途才切換評分方式很麻煩，而且每份作業都要在 E3 網頁上重新定義題目。
  - 依上游行為，grader 在 iPad 上的評分面板很窄。
  - 用 API 讀「準則的 ID」要靠 `core_grading_get_definitions`，但 E3 的行動版服務**沒有開這個函式**（`functions.txt` 裡只有 `mod_assign_*` 和 `core_files_*`）。所以 `mod_assign_save_grade` 的 `advancedgradingdata` 實際上送不出去。

學姊希望怎麼做：

> 「每份作業先設好『共 6 題，每題 5 分』，畫面上每題一排 0 到 5 的大按鈕，用 Apple Pencil 點就好，總分自動算，再一起送出。學生那邊看到的評語就是一張小表格：『Q1 5 · Q2 3 · Q3 2（第三題積分範圍錯）……』。E3 上的成績只要總分就好。」

## 痛點（依嚴重度排序）

1. **改完的檔案對不回學生（嚴重）。** 比對完全依賴檔名裡的 7 位數參與者編號，但人看不懂這串數字，GoodNotes 匯出時也不會保留。對不上的檔案會被略過，不會有警告。
2. **繳交檔案格式亂，要手動整理（嚴重）。** 一個人好幾張圖、方向錯、HEIC。E3 的 zip 只是把原檔照原樣打包。
3. **分數要打兩次，每題分數沒地方存（嚴重）。** 「給分指引」可以做到，但每份作業都要在網頁上設定，iPad 上很難操作，API 也送不出去。
4. **iPad 上的 E3 不能拿來評分（高）。** 表格溢出、選單佔掉空間、grader 是桌機版面，所以她一定要在 iPad 和筆電之間搬檔案。
5. **兩個班要各做一次（中）。** 下載、上傳、打分數全部 ×2。
6. **說明藏在「?」裡（中）。** 上傳頁沒有直接寫出命名規則，也沒有「先檢查 zip」的功能。
7. **E3 的批註 PDF 不能取代 GoodNotes（中）。** 一次一個學生，筆的手感差，不會自動轉正。
8. **頁面一開就寫入偏好（低，但值得注意）。** grader、快速評分、資料夾下載、成績簿導覽都會寫入使用者偏好。

## 需求

**Must**

- 一次拿到「每位學生一份 PDF」：圖片自動轉正、合併，檔名是人看得懂的「〈學號〉_〈姓名〉_〈作業〉.pdf」，而且可以直接在 iPad 上取得。
- 把改好的 PDF 整批丟回來，系統依學號自動配對學生，**上傳前先顯示配對表**（已配對、找不到、重複），確認後再回傳。
- 依題給分：設定題數和每題滿分，點選分數，自動加總，總分寫進 E3，每題分數寫進評語。
- 平板版面可以完成「看名單 → 給分 → 回傳」。

**Should**

- 跨班（跨課程）的同名作業合併成一個批改佇列。
- 進度：已改、已回傳、未交，各有多少份。
- 可以從試算表貼上「學號、分數」兩欄，批次寫入分數。

**Could**

- 在 EM3 裡用 Apple Pencil 直接批註，不必經過 GoodNotes。
- 依每題分數產生統計，例如每題的平均分數，讓她知道哪一題全班都錯。
- 一鍵寄出「第 N 題常見錯誤」的公告。

## 對朋友假設的判斷

| 假設 | 判斷 | 理由 |
| --- | --- | --- |
| 「評分很重要，我最常用評分」 | **完全同意** | 她每週有 10 小時以上花在評分相關的事情，一半是雜事。 |
| 「把作業下載下來，改完再上傳回去」 | **同意，但重點要修正** | 下載和上傳本身只要 1–2 次點擊，真正痛的是前後兩頭：**下載後的格式整理**和**上傳時的學生配對**，再加上**分數要另外打**。功能應該設計成「批改往返」，而不是「下載＋上傳按鈕」。 |
| 「建立小考」 | 不需要 | 微積分的小考都是紙本，在課堂上考。她頂多需要「紙本小考分數批次輸入」，那屬於評分。 |
| 「Markdown 編輯、新增不同的文件」 | 不需要 | 教材由老師上傳，助教不編教材。偶爾會貼解答 PDF，用 E3 的教材管理就夠了。 |

## 功能排序與 EM3 提案

| 排名 | 功能 | 內容 | API 可行性 |
| --- | --- | --- | --- |
| 1 | **批改往返：回傳** | 把一個資料夾或多個 PDF 拖進 EM3（iPad 上用「檔案」App 選取）。依檔名開頭的學號，或下面第 2 項嵌入的代碼，配對學生，顯示配對表：✅ 已配對、⚠ 找不到、⚠ 一人多檔、⚠ 已經有回饋檔案。確認後逐一上傳，並顯示進度。 | **可行**。流程是 `/webservice/upload.php`（filearea=draft）→ 拿到 draft itemid → `mod_assign_save_grade`，`plugindata.files_filemanager=itemid`。配對直接用 userid，**完全不需要 zip 命名規則**。要注意：save_grade 必須同時送 grade，只回傳檔案時的 grade 值要先用測試作業驗證；要保留舊的回饋檔案時，要先把舊檔一起放進 draft。 |
| 2 | **批改往返：打包** | 選一份作業（可以跨兩個班），EM3 抓下每位學生的所有檔案，在瀏覽器端：依 EXIF 轉正圖片 → 把圖片和 PDF 依上傳順序合併成一份 PDF → 命名為 `〈學號〉_〈姓名〉_HW3.pdf` → 打包成 zip，或用分享面板直接送到 GoodNotes。可以只打包「還沒改的」或「新交的」。 | **可行**。`mod_assign_get_submissions` 取得檔案 URL，加 token 下載，用 pdf-lib 加 canvas 合併。HEIC 只有 Safari 能解碼，其他瀏覽器要提示。120 份照片可能有幾百 MB，要分批處理並顯示進度。 |
| 3 | **依題給分面板** | 每份作業設定「題數 N、每題滿分 5」（存在本機，可以匯出）。每位學生一排 0–5 的大按鈕，Apple Pencil 和鍵盤都能操作，輸入數字後自動跳到下一題，總分即時算出。也可以設定換算比例，例如 6 題 × 5 分換算成 100 分。儲存時總分寫進 grade，每題分數寫成評語裡的表格；下次打開時從評語讀回來，所以 iPad 和筆電之間不用同步。 | **可行**。單筆用 `mod_assign_save_grade`（grade＋`assignfeedbackcomments_editor`），批次用 `mod_assign_save_grades`。讀回用 `mod_assign_get_submission_status`（帶 userid，回傳 feedback plugins）。**不建議**用 E3 的「給分指引」：定義要在網頁上建立，而且 `core_grading_get_definitions` 不在 E3 的行動版服務裡。已經在用給分指引的作業，就提供「在 E3 開啟 grader」的捷徑。 |
| 4 | **平板批改清單** | 一個學生一列：學號、姓名、狀態（未交／待改／已給分／已回傳）、總分、檔案數。依學號排序，可以篩選，點一下就開右側面板（預覽、給分、回傳）。1024 寬時不會出現橫向捲動。 | **可行**。用 `mod_assign_list_participants`、`mod_assign_get_submissions`、`mod_assign_get_grades`。 |
| 5 | **貼上分數** | 從 Google Sheets 或 Numbers 貼上「學號 ⇥ 分數」，或每題分數的多欄資料。EM3 配對學生後顯示預覽和差異（舊分數 → 新分數），確認後批次寫入。也可以產生 E3 成績簿用的 CSV 當作備案。 | **可行**。用 `mod_assign_save_grades`；CSV 則交給 E3 的 `/grade/import/csv/` 匯入。 |
| 6 | **跨班合併** | 兩門課裡名稱相同、截止時間相同的作業，可以合併成一個佇列，進度一起計算。 | 純前端。 |
| 7 | 題目統計 | 依每題分數畫出平均和分布。 | 純前端，資料來自第 3 項的評語表格。 |
| 8 | 內建 Pencil 批註 | 在 EM3 的 PDF 預覽上用 Pencil 畫，存成回饋 PDF。 | 技術上可行（canvas 加 pdf-lib，再接第 1 項上傳），但成本高，而且她不會放棄 GoodNotes。**低優先**。 |
| – | 建立小考、Markdown 教材 | – | 沒有 API，對這個角色也不需要。 |

**配對的設計重點**：打包時把一個短代碼放進檔名，例如 `〈學號〉_〈姓名〉_HW3_em3-〈userid〉.pdf`。這樣就算她在 GoodNotes 改了檔名，只要開頭的學號還在就配得到。學號和代碼都不見時，配對表會列出「找不到」，讓她從下拉選單手動指定。**不要沿用 E3 那串只有機器看得懂的參與者編號。**

**實作前要用測試作業驗證的事**：

- 用 `mod_assign_save_grade` 只傳檔案、不給分時，grade 該送什麼值。
- 回饋檔案的 draft 區是整批取代還是累加。
- 「通知學生」在 API 上要怎麼控制。
