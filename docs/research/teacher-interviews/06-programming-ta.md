2026-10-15 進行。這是一場模擬訪談：受訪者的話由 agent 依角色設定扮演；E3 上的操作、檔名格式、CSV 欄位、API 結構都是在 E3 實際觀察到的。觀察使用唯讀的教師帳號（課程 23571，作業「期末報告」cmid 218500 / assignid 40340），瀏覽器視窗 1920×1080。

## 2. 訪談重點

### 每週的流程

> 「流程固定是：截止隔天早上從 E3 下載全部 → 解壓 → 跑我的腳本整理資料夾 → 跑 autograder → 產分數 CSV → 把分數弄回 E3 → 接下來一週處理遲交、申訴、改判。最花時間的不是改，是**資料搬來搬去**。」

> 「下載本身很快，問題在下載完的資料夾名字。E3 的資料夾是『學號 系所 縮寫 姓名_一串數字_assignsubmission_file』，中間有兩個空格，有人有學號、有人沒有，數字也不是學號。我每學期都要重寫 regex。」

> 「我最在意的一件事：**E3 作業裡沒有『用學號匯入分數』這個按鈕。**作業的評分工作表要用『參與者 1234』這種識別碼比對，可是我的 autograder 只知道學號。我得先下載工作表，再用學號去 join。」

> 「CSV 是最常爆的地方。我用 LibreOffice 存是 UTF-8，另一個助教用 Windows Excel，存出來是 Big5。上傳的時候編碼預設是 UTF-8，名字變亂碼，或者整欄對不上。」

### 每一步花多少時間（受訪者自估，每週，只算自己負責的 40 人）

| 步驟                                              | 時間                            | 卡住的地方                                                                             |
| ------------------------------------------------- | ------------------------------- | -------------------------------------------------------------------------------------- |
| 1. 找到作業 → 繳交概況 → 下載全部                 | 3–5 分鐘                        | 下載的是全班 200 人，沒辦法只抓自己那組                                                |
| 2. 解壓、改資料夾名稱                             | 10–15 分鐘                      | 資料夾命名不一致、學生交 `.rar` / `.7z`、`main.cpp` 包在多層資料夾裡、檔名有中文或空白 |
| 3. 跑 autograder                                  | 機器跑 10 分鐘，人工 20–30 分鐘 | 編譯失敗要人工看：CRLF、Big5 註解、`#include <bits/stdc++.h>`、檔名打錯                |
| 4. 產生分數 CSV                                   | 5 分鐘                          | 這步沒問題                                                                             |
| 5. 把分數放回 E3                                  | 20–30 分鐘                      | 工作表要用參與者編號比對；或者在網頁上逐筆輸入 40 人；Excel 編碼問題                   |
| 6. 回傳每人的批改報告（編譯錯誤、哪幾筆測資沒過） | 平常不做，太麻煩                | 回饋 zip 也要用「姓名_參與者編號」命名，名字錯一個字就對不上                           |
| 7. 遲交                                           | 每週 15–20 分鐘                 | 要從「已繳交 - 過期 N 小時 N 分鐘」這種文字自己換算扣分                                |
| 8. 申訴、改判                                     | 每週 20–40 分鐘，高峰時 1 小時  | 要在 200 人的表裡找到那一位，打開單一評分頁，改分、寫原因                              |

> 「整體大概每週 2 到 3 小時。真正『改』的部分是電腦在跑，我的時間都花在第 2、5、7、8 步。」

### 多次繳交與遲交

> 「我們允許截止前重交，以最後一次為準。截止後到關閉前（大約兩天）可以遲交，每 24 小時扣 10%。我想要的是一個欄位直接告訴我『晚了幾秒』，而不是一句中文。」

> 「有同學被准許延期，E3 表格上看得到『授予的擴展』，可是我下載的 zip 裡完全沒有這個資訊，autograder 會照樣扣他分數。」

> 「重交的情況下，我需要知道『上次下載之後有誰重交了』。現在只能整包重新下載，再 diff 整個資料夾。」

### 分組與 5 位助教

> 「助教分工靠一張 Google Sheet，寫『學號 1 到 40 號給 A』。E3 上沒有建分組，因為老師說建分組很麻煩。如果 E3 上有『只看我這組』的篩選，我每週可以省下一半的整理時間。」

> 「最怕的是兩個助教同時改同一個人，後上傳的把先上傳的蓋掉。」

### 鍵盤

> 「我不想用滑鼠一筆一筆點。申訴改判時，我想要：搜尋學號 → Enter → 輸入分數 → Tab 到評語 → Ctrl+Enter 存檔，然後跳下一位。」

## 3. 觀察紀錄（E3 實測）

所有時間都是從 `page.goto` 到 `load` 事件。教師頁面在這次測試都在 0.4–0.75 秒內載完，比學生研究裡的首頁、成績頁（7–9 秒）快很多。不過資料只有 26 人，200 人時會更慢。

### T1　繳交概況（評分表）

- 網址 `/mod/assign/view.php?id=218500&action=grading`，載入 549–732 ms。
- 從課程頁進來：作業 → 「繳交概況」分頁，共 2 次點擊。也可以從側欄「作業管理」（E3 自製頁面）→「檢視」→「繳交概況」，共 3 次點擊。
- **版面**：1920 寬的螢幕上，第一屏只看得到 **1 列**學生。「狀態」欄只有 93 px 寬，「未繳交 已經超過應繳交…」變成一個字一行的直排。26 人、每頁 50 筆時，整頁高 7,868 px（平均每列約 300 px，因為「線上文字」欄會把全文攤開）。換成 200 人的課，就算是只交檔案的作業，也要捲很多屏。
- **欄位**：選取、所屬系所 / 姓名、帳號、電子郵件信箱、狀態、成績、最後修改的(作業)、線上文字、作業加備註、最後修改的(得分)、評語回饋、批註的PDF檔、回饋檔案、最終成績。
- **篩選**：搜尋用戶、依名稱篩選（字首）、狀態（全部 / 尚未繳交 / 草稿 / 已繳交 / 需要評分 / 授予的擴展）、進階（包含已停權的課程成員）、每頁 10 / 20 / 50 / 100 / 所有。這門課沒有分組（`groupmode=0`），所以**沒有分組篩選**。有分組時 Moodle 會多一個分組下拉選單。
- **「動作」選單**：檢視成績單、以一個壓縮檔上傳多個回饋檔案、下載全部繳交的作業。**沒有**「下載評分工作表」和「上傳評分工作表」，因為作業設定裡的「離線計分試算表」沒有勾選。
- **每列的 ⋮ 選單**：防止作業更改、准許延期、刪除作業（有繳交的才有）；成績欄的 ⋮：成績。
- **全選後的底部工具列**：鎖定作業、解除鎖定作業、下載、刪除、更多（「延伸」、「Upload feedback」）。「延伸」和「授予的擴展」都是 _extension_（延期）的誤譯，「Upload feedback」沒有翻譯。
- 「以分開的資料夾方式下載繳交的檔案」預設是勾選的。

### T2　下載全部繳交的作業（只記錄命名，下載後立即刪除）

- 點擊路徑：繳交概況 → 動作 → 下載全部繳交的作業，共 3 次點擊。網址是 `?id=218500&action=downloadall`（一般 GET）。
- 26 人中 22 人有繳交（只有線上文字），zip 10 KB，117 ms 下載完。
- **zip 檔名**：`{課程簡稱}-{作業名稱}-{cmid}.zip`，例如 `ICT.20260316-期末報告-218500.zip`
- **zip 內的路徑**（勾選「分開的資料夾」時）：

  ```
  {顯示名稱}_{參與者編號}_assignsubmission_{plugin}/{檔名}
  例：〈學號〉 〈系所中文簡稱〉  〈系所英文縮寫〉 〈姓名〉_〈參與者編號〉_assignsubmission_onlinetext/onlinetext.html
  ```

  - 22 個資料夾中，21 個的顯示名稱是 4 段，1 個是 3 段（沒有系所）。系所與縮寫之間原本是「 / 」，被換成**兩個空格**。
  - 開頭的數字大多是學號，但有幾個和 `core_grades_get_gradable_users` 回傳的 `idnumber` 對不上。也就是說，**不能假設資料夾名稱的第一段一定是學號**。
  - `{參與者編號}` **不是學號，也不是 Moodle userid**。它是這份作業專用的匿名編號，和 `mod_assign_get_user_mappings` 的 `id` 一致（22/22 筆符合）。
  - 檔案繳交的作業，`{plugin}` 會是 `file`，資料夾內是原始檔名。這是依 Moodle 4.5 原始碼推論的，這份作業沒有開檔案繳交，沒有實測。沒勾「分開的資料夾」時，Moodle 會把路徑攤平成 `{顯示名稱}_{參與者編號}_assignsubmission_file_{檔名}`（同樣是推論）。

- 下載的檔案已經刪除，掃描時沒有開啟或保存任何繳交內容。

### T3　評分工作表（離線計分試算表）

- 選單裡沒有，但直接用網址 `?id=218500&plugin=offline&pluginsubtype=assignfeedback&action=viewpluginpage&pluginaction=downloadgrades` 仍然可以下載（131 ms）。已刪除。
- **檔名**：`分數-{課程簡稱}-{作業名稱}-{cmid}.csv`
- **編碼**：UTF-8 **有 BOM**，逗號分隔，換行是 LF（不是 CRLF）。
- **欄位標題**（這份作業共 12 欄，會隨啟用的繳交與回饋外掛增減）：

  ```
  識別碼, 完整名稱, 帳號, 電子郵件信箱, 狀態, 成績, 最高成績, 分數可以被更改, 最後修改的(作業), 線上文字, 最後修改的(得分), 評語回饋
  ```

- **欄位格式**（不含實際值）：
  - `識別碼` = `參與者{參與者編號}`
  - `帳號` = 學號（大多數是 9 位數字，少數是其他長度）
  - `狀態` 是一串組合文字，例如 `已繳交 - 過期{N} 小時 {N} 分鐘 -  - `、`未繳交 - 已經超過應繳交時間: {N} 日 {N} 小時 -  - `。遲交時間只寫在這段中文裡，沒有獨立的數字欄
  - `最高成績` = `{N}.{N}`；`分數可以被更改` = `是`
  - 兩個「最後修改」欄是 `{YYYY}年 {MM}月 {D}日(週X) {HH}:{mm}`，在地化格式，不是 ISO 8601
  - `線上文字` 會把學生的全文直接放在 CSV 裡
- **上傳頁**（`pluginaction=uploadgrades`）：上傳一個檔案、編碼（預設 UTF-8，下拉選單約 80 種，含 CP950 / BIG5）、分隔符號（預設逗號）、「如果評分試算表比較新，允許更改已評分登記的紀錄」（預設不勾）。說明文字寫「檔案必須是以 UTF-8 編碼」。
- **比對方式**：用「識別碼」（參與者編號）比對，**不是學號**。依 Moodle 原始碼，欄位是用目前介面語言的欄名比對的，所以用英文介面下載、再用中文介面上傳會對不上（推論，未實測）。
- 預設會拒絕覆寫「下載工作表之後才被別人改過」的分數，這正好可以避免多位助教互相覆蓋。不過畫面上只用一個勾選框說明。

### T4　以一個壓縮檔上傳多個回饋檔案

- 點擊路徑：動作 → 以一個壓縮檔上傳多個回饋檔案 → 選擇一檔案…（Moodle 檔案挑選器）→ 匯入回饋檔案 → 確認頁 → 確認。至少 6 次點擊，還要加上挑選器裡的步驟。
- 只接受 `.zip`。
- 頁面上的說明原文：「指派給學生的回饋檔，其檔名的構成是使用者完整姓名加上識別編號。這一命名上的慣例也適於在下載學生的作業，這樣您就可以下載全部作業，在一些檔案上加上評語，然後重新壓縮並上傳傳布的檔案。沒有變更的檔案將被忽略。」
- 換句話說，**上傳時的命名規則**和下載時一樣：`{顯示名稱}_{參與者編號}_…`，靠參與者編號比對。autograder 產生的 `{學號}.txt` 不能直接上傳，要先轉換檔名。

### T5　單一評分頁（grader）

- `?id=218500&action=grader` 的外框 454 ms 就出來了，但在唯讀環境中，它載入時送出的偏好設定 POST（`/r.php/api/rest/v2/user/current/preferences`）被攔下，結果跳出「TypeError: Failed to fetch」，左右兩個面板一直停在載入中。這是測試環境造成的，不是 E3 的問題，所以這次沒有評估評分頁本身的鍵盤操作。
- 看得到的元素：課程與作業連結、「變更使用者」下拉選單與左右箭頭、「總共 26 位，此為第 5 位」、篩選、底部的「通知學生」（預設勾選）、「儲存變更」、「儲存後顯示下一位」、「重置」，以及三個版面配置按鈕。頁面上沒有 `accesskey` 或 `aria-keyshortcuts`。

### T6　課程層級的成績匯入與匯出（用學號比對的路徑）

- `/grade/import/csv/index.php?id=23571`（453 ms）：核心的 CSV 匯入。說明寫「其中一個欄位名稱必須要包含使用者的身分資料，不管是使用者名稱、ID 編號或 EMAIL 位址」，所以**可以用學號（帳號）比對**。編碼預設 UTF-8，另有預覽行數和強制匯入選項。
- 但 E3 側欄的「成績管理」是自製頁面（`/local/courseextension/grade/…`），裡面的選項有總成績、個人成績、全班微調、個人微調、給分方式、匯出、配分方式、編輯成績，**沒有「匯入」**。核心的匯入頁只能直接打網址進去。
- 匯出（`/grade/export/txt`）可以勾選要匯出的成績項目、是否包含回饋、排除休學學生、顯示類型、小數位數、分隔符號。

### T7　作業設定裡和助教分工有關的選項（只檢視，未儲存）

`/course/modedit.php?update=218500` 有這些欄位：離線計分試算表、回饋檔案、批註的 PDF 檔、重繳次數限制、群組繳交、匿名受評、**全部評完才公佈**（marking workflow）、**指定評分者**（marking allocation）、群組模式、Turnitin。換句話說，E3 本身支援「把學生指派給特定助教」，但要老師先開啟評分流程，而且畫面上沒有任何說明。

## 4. API 觀察（唯讀實測，值都換成佔位符）

### 4.1 用學號建立資料夾需要串四支 API

| 需要的資料                   | 來源                                                                                         | 備註                                                      |
| ---------------------------- | -------------------------------------------------------------------------------------------- | --------------------------------------------------------- |
| 學號                         | `core_grades_get_gradable_users(courseid, groupid?, onlyactive?)` 的 `username` / `idnumber` | 這門課 26 人都有，兩欄相同，25 人是 9 位數、1 人是 7 位數 |
| 繳交狀態與檔案               | `mod_assign_get_submissions`                                                                 | 只回傳**最新一次**嘗試                                    |
| 參與者編號                   | `mod_assign_get_user_mappings`                                                               | 要和 E3 的 zip、工作表互通時才需要                        |
| 誰需要評分、是否准許延期     | `mod_assign_list_participants`                                                               | **沒有** username / idnumber；Email 前綴也不是學號        |
| 延期日期、指派的評分者、鎖定 | `mod_assign_get_user_flags`                                                                  | 這份作業回傳 warning code `3`「No user flags found」      |
| 分組                         | `core_group_get_course_groups`、`core_group_get_activity_allowed_groups(cmid)`               | 這門課是空的；`canaccessallgroups=true`                   |

`core_enrol_get_enrolled_users` 對學生回傳的 `username` 和 `idnumber` 是空字串，所以**學號一定要從 `core_grades_get_gradable_users` 拿**。

### 4.2 JSON 結構

		"id": 0,

		"firstname": "…",
		"lastname": "〈系所 / 縮寫〉",
		"email": "〈mail〉",
		"suspended": false,
		"recordid": 0,
		"roles": [{ "roleid": 0, "name": "…", "shortname": "student|guest", "sortorder": 0 }],

		"firstaccess": 0,

		"description": "",
		"descriptionformat": 1,
		"city": "",
		"country": "",

```

- 回傳的 26 人裡有 5 人的角色是 `guest`，客戶端要依 `roles[].shortname` 篩掉。
- `recordid` 和參與者編號不同（0/26 相符），不要拿來對應工作表的「識別碼」。
- `enrolledcourses` 會列出這位學生修過的全部課程（最多看到 50 門），回應因此很大（26 人就有 166 KB）。200 人時要注意。

											"filename": "main.cpp",
											"filepath": "/",
											"filesize": 0,
											"fileurl": "https://…/webservice/pluginfile.php/…",
											"timemodified": 0,
											"mimetype": "text/x-c++src",
											"isexternalfile": false

					]
				}
			]
		}
	],
	"warnings": []
}
```

- `file` 外掛的 `files[]` 欄位是依 Moodle 4.5 的 external_files 定義寫的；這份作業沒有檔案繳交，所以沒有實測。
- 實測結果：27 筆中 22 筆是 `submitted`、5 筆是 `new`，全部是 `notgraded`，`attemptnumber` 都是 0。
- 下載檔案要在 `fileurl` 後面加上 `?token=…`，EM3 的 PDF 預覽已經用 blob 的方式處理過同樣的情況。

`mod_assign_get_grades 'assignmentids[0]=…'`

```json
{ "assignments": [{ "assignmentid": 0, "grades": [{ "id": 0, "userid": 0, "attemptnumber": 0, "timecreated": 0, "timemodified": 0, "grader": -1, "grade": "-1.00000" }] }], "warnings": [] }
```

- **22 筆都是 `"-1.00000"`，`grader` 也是負數**：有成績列不代表已經評分，`-1` 要當作「未評分」處理。
- `grade` 是字串，客戶端要自己轉成數字。
- 有 4 筆的 userid 不在 participants 裡（可能已退選或角色改變），匯入時要另外列出來。

`mod_assign_get_user_mappings` → `{ "assignments": [{ "assignmentid": 0, "mappings": [{ "id": 〈參與者編號〉, "userid": 0 }] }] }`。共 32 筆，比目前的 26 人多，因為包含過去的成員。

`core_grades_get_gradable_users courseid=…` → `{ "users": [{ "id": 0, "username": "〈學號〉", "idnumber": "〈學號〉", "fullname": "…", "email": "…", "department": "", "suspended": false, … }] }`

`mod_assign_get_assignments` 中和這次有關的欄位：`duedate`、`cutoffdate`（這份作業比截止晚 45.5 小時）、`gradingduedate`、`attemptreopenmethod`（`untilpass`）、`maxattempts`（`-1`）、`teamsubmission`、`blindmarking`、`markingworkflow`、`markingallocation`、`configs[]`（例如 `assignfeedback/file/enabled=1`；沒有 `offline`）。

### 4.3 寫回 E3（這些 API 存在，這次沒有呼叫）

```json
mod_assign_save_grades {
  "assignmentid": 0, "applytoall": 0,
  "grades": [{ "userid": 0, "grade": 87.5, "attemptnumber": -1, "addattempt": 0,
               "workflowstate": "",
               "plugindata": { "assignfeedbackcomments_editor": { "text": "〈評語〉", "format": 1 },
                               "files_filemanager": 〈draftitemid〉 } }]
}
```

- **回饋檔案**：每位學生先透過 `/webservice/upload.php`（`itemid=0` 會產生新的 draft）上傳檔案，再把 draftitemid 填進 `files_filemanager`。檔案會整批取代，所以要保留舊的回饋檔，就得先下載再重新上傳，做法和 EM3 現在的繳交流程一樣。
- **延期**：`mod_assign_save_user_extensions { assignmentid, userids[], dates[] }`
- **指派評分者與評分流程狀態**：`mod_assign_set_user_flags`（有 `allocatedmarker`、`workflowstate`，這個帳號的 token 可以呼叫）
- **鎖定、退回草稿**：`mod_assign_lock_submissions` / `unlock` / `revert_submissions_to_draft`

## 6. 需求

### Must

1. **下載 zip，資料夾依學號命名**（`{學號}/原始檔名`），附 `manifest.csv`，列出每位學生的繳交時間、遲交秒數、延期截止、嘗試次數。
2. **可以篩選下載範圍**：依分組或指派的助教、依狀態（需要評分、上次下載後有變動）。
3. **用學號匯入分數 CSV**：自動判斷編碼（UTF-8 / BOM / Big5）和分隔符號，先預覽新舊分數差異，再寫回。
4. **衝突保護**：寫回前比對 `get_grades.timemodified`，如果別的助教在我下載後改過分數，就停下來讓我決定。

### Should

5. **回饋檔 zip 依學號回傳**：`{學號}.txt`、`{學號}/report.html` 都要能認得。
6. **鍵盤評分**：搜尋學號、j/k 切換學生、直接輸入分數、評語範本、Ctrl+Enter 存檔並跳下一位。
7. **遲交與延期面板**：依 manifest 算出扣分建議；可以批次延期。
8. **只顯示「我的組」的進度**：40 人中已改、未改、有申訴各幾人。

### Could

9. 改判紀錄：記錄誰、何時、從幾分改成幾分、原因（存在本地，或寫進評語）。
10. 匯出 E3 相容格式，例如用 `{顯示名稱}_{參與者編號}` 命名的 zip，讓沒用 EM3 的助教也能用。

## 8. 理想的 EM3 評分流程（200 人、5 位助教）

### 8.1 前置：分工

- 第一次打開作業時，EM3 讀取 `core_group_get_course_groups`。
  - **有分組**：顯示「我的組」切換，用 `core_grades_get_gradable_users groupid=…` 或 `mod_assign_list_participants groupid=…` 拉名單。
  - **沒有分組**：提供「學號區間 / 貼上學號清單」的**本地分組**，存在 `em3:prefs` 裡，可以匯出 JSON 給其他助教。不寫進 E3，因為沒有建立分組的 API。
  - 老師有開「指定評分者」時，讀 `mod_assign_get_user_flags.allocatedmarker`，預設篩選「指派給我」。
- 頁首固定顯示這一組的進度：`我的組 40 人 · 已交 37 · 需評分 12 · 已評 25 · 延期 2`。

### 8.2 下載

一個「下載」按鈕，打開一個面板：

```
範圍：  ● 我的組 (40)   ○ 全班 (200)   ○ 勾選的 (3)
狀態：  ☑ 已繳交  ☐ 未繳交（留空資料夾）  ☐ 只抓上次下載後有變動的 (5)
命名：  ● {學號}/原始檔名   ○ {學號}_{原始檔名}（攤平）   ○ E3 相容（顯示名稱_參與者編號）
附加：  ☑ manifest.csv   ☑ 線上文字存成 onlinetext.html
```

- 在瀏覽器端用 fflate 這類函式庫串流打包。檔案透過 `fileurl` 加 token 下載，同時下載數限制在 4 個。
- `manifest.csv`（UTF-8，**不加 BOM**，LF 換行，方便 Linux 工具處理）：

  ```
  student_id,userid,status,attempt,submitted_at_iso,late_seconds,due_iso,extension_due_iso,files
  〈學號〉,〈userid〉,submitted,0,2026-06-01T01:23:00+08:00,4980,2026-06-01T00:00:00+08:00,,main.cpp;README.md
  ```

- 「只抓有變動的」：用上次下載時記下的 `submission.timemodified`（存在本地）做比對。
- 下載完成後顯示摘要：`40 人 · 37 份 · 1.8 MB · 3 人遲交 · 1 人延期中`。

### 8.3 評分：手動與鍵盤

- 左邊是學生清單（只有我的組），右邊是檔案預覽。`.cpp`、`.txt`、`.md` 用等寬字型，有語法高亮；PDF 沿用 EM3 現有的預覽。
- 快捷鍵：`/` 搜尋學號或姓名、`j`/`k` 上下一位、`g` 移到分數欄、`c` 移到評語、`1`–`9` 插入評語範本、`⌘/Ctrl+Enter` 儲存並跳下一位、`e` 延期、`?` 顯示所有快捷鍵。
- 儲存呼叫 `mod_assign_save_grade`。存檔前先讀一次 `get_grades`，如果 `timemodified` 比我開啟這位學生時還新，就提示「〈助教B〉剛剛改過」。
- 評語範本存在本地，可以匯出給其他助教。

### 8.4 匯入分數 CSV

1. 把 CSV 拖進來。
2. **自動判斷**：
   - 編碼：有 BOM 就是 UTF-8；否則先用 `TextDecoder('utf-8', {fatal:true})` 解碼，失敗就改用 `big5`。
   - 分隔符號：逗號、Tab、分號。
   - 欄位：名稱像 `學號|student_id|帳號|username|id` 的當作學號欄；`分數|grade|score` 是分數欄；`評語|feedback|comment` 是評語欄。

   每一項都可以手動修改。

3. **E3 工作表也接受**：看到 `識別碼` 欄就用 `get_user_mappings` 換成 userid。
4. **預覽**：

   ```
   將更新 38 筆 · 不變 2 筆 · 找不到 1 筆（〈學號〉不在名單） · 超出 0–100 範圍 0 筆
   ⚠ 2 筆在你下載之後被其他人改過：〈學生A〉 80 → 你的 85（E3 目前 83）
   ```

   清單用三欄對照：舊分數 → 新分數 → 差異。

5. 按「寫回 E3」：呼叫 `mod_assign_save_grades`，每批 20 人，顯示進度。失敗的列另外標出來，可以單獨重試。
6. 每位學生的「通知學生」預設關閉；整批寫完後，再決定要不要統一通知。

### 8.5 回傳回饋檔案

- 把 zip 或資料夾拖進來，比對規則依序是：
  1. 資料夾名稱是學號
  2. 檔名開頭是學號（`/^(\d{7,10})[_\-. ]/`）
  3. E3 格式：`_{參與者編號}_`
- 預覽：`37 位學生 · 37 個檔案 · 未比對 2 個（README.txt、.DS_Store）`
- 寫回：逐位學生上傳到 draft，再用 `save_grade` 的 `files_filemanager` 寫入。如果這位學生在同一批 CSV 裡也有分數，就合併成一次呼叫。
- 選項：「保留 E3 上原本的回饋檔」（先下載舊檔，再一起上傳）或「取代」。

### 8.6 遲交、延期、申訴

- **遲交欄**用 `late_seconds` 加上課程設定的扣分規則（本地設定，例如每 24 小時扣 10%），算出「建議扣分」，助教確認後才寫入。
- **延期**：選學生 → 選日期 → `mod_assign_save_user_extensions`。延期中的學生在清單裡有標記，manifest 也會寫出延期截止時間。
- **申訴**：在單一學生頁按「改判」，填新分數和原因。原因會附加到評語的最後（`[改判 10/15] 〈原因〉`），同時寫進本地的改判紀錄。

### 8.7 E3 做不到、要跳轉的部分

開啟「離線計分試算表」、開啟「指定評分者」、建立分組，這些都沒有 API。EM3 只顯示一行說明，並提供按鈕直接開啟對應的 E3 設定頁（`/course/modedit.php?update={cmid}`、`/group/index.php?id={courseid}`）。

## 10. 實作注意事項（給 EM3 開發）

- **學號只能從 `core_grades_get_gradable_users` 取得。** `list_participants` 和 `get_enrolled_users` 都拿不到。
- `get_grades` 的 `"-1.00000"` 代表未評分。`list_participants` 會包含 `guest` 角色。`get_submissions` 只回傳最新一次嘗試。
- `list_participants` 的 `enrolledcourses` 會讓回應變得很大，200 人時要先估算大小，或改用 `get_gradable_users` 加 `get_submissions` 組合資料。
- 寫入的 API 要用測試作業驗證之後才能上線。這次研究完全沒有呼叫任何寫入 API。
- CSV 和 zip 都在瀏覽器端處理，學生資料不經過第三方伺服器。這一點要寫在 UI 上，因為助教處理的是 200 人的個資。
