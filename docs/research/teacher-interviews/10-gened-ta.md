# 教師／助教訪談 10：通識課助教小雅（三位助教分工、評分一致性、統一公布、成績申訴信）

> 方法：模擬訪談，加上用真實 `editingteacher` 帳號在 E3（Moodle 4.5）唯讀觀察，課程 23571。Playwright 視窗設成 1366×768，模擬一般 Chromebook 的螢幕；透過 `scripts/e3-browser.mjs` 操作，它會擋下所有非 GET 請求。時間是 `networkidle` 的量測值，測於 2026-10-15。全程沒有儲存、評分、寄信，也沒有切換編輯模式。郵件只看列表，沒有點開任何一封。截圖和下載都留在 scratchpad，沒有放進 repo。
>
> 觀察限制，請一併閱讀：
>
> - 課程 23571 和 23502 **都沒有任何群組或集群**（`core_group_get_course_groups`／`core_group_get_course_groupings` 都回傳 `[]`）。三份作業也都**沒有開**評分工作流程、指定評分者、群組繳交和匿名評分（`mod_assign_get_assignments`）。所以「依評分者篩選」「依工作流程狀態篩選」「依群組評分」「套用到整組」這些介面**無法實際看到**，以下對它們的描述來自 Moodle 4.5 的標準行為，都標成「未實測」。
> - 單一評分頁（`action=grader`）載入時會送出 `POST /r.php/api/rest/v2/user/current/preferences`，唯讀瀏覽器把它擋掉了，結果跳出 `TypeError: Failed to fetch`，評分面板一直停在轉圈。所以只看到外框：頂部的「變更使用者」、「總共26位，此為第5位」，底部的「通知學生 ☑」「儲存變更」「儲存後顯示下一位」「重置」。面板裡的欄位**沒有觀察到**。
> - 「建立新郵件」的連結是 `GET /local/dcpcmail/create.php?c=23571&sesskey=…`，帶 sesskey 的 GET 很可能會直接建立一封草稿，所以**沒有打開**。撰寫畫面（能不能選群組、角色當收件人）沒有觀察到。
> - 「下載全部繳交的作業」沒有實際下載，壓縮檔結構請參考其他份訪談。

## 受訪者（Persona）

**小雅**，26 歲，人社院碩士生，通識課「認同與文化」的助教。

- 三個時段合計 180 人。教授請系上把三個時段併成同一個 E3 課程，和另外兩位助教**一人負責一個時段**（各約 60 人、12 組）。
- 作業有兩種：**分組報告**（簡報＋書面，一組 5 人，同組同分再個別微調）和**個人心得**（每兩週一篇，約 1,000 字）。兩種都用 rubric 評分，rubric 有 4 個面向、每個面向 4 個等級。
- 教授的硬性規定：
  1. 三位助教的評分標準要一致。
  2. 三個時段要**同一時間公布成績**。
  3. 申訴一週內處理完畢。
- 設備是學校借的 **Chromebook**，只能用瀏覽器。三位助教共用一份 **Google Sheets** 評分表，分工和進度也都記在裡面，平常用 LINE 群組協調。
- 學生問成績、要求重看時，幾乎都是寄 **E3 站內信**（「我的郵件」），很少用學校 email。

## 訪談摘錄

**分工**

> 「我們是一人一個時段。分組報告一個時段大概 12 組，我就看我那 12 組，個人心得也是看我那 60 個人。可是 E3 不知道誰負責誰。我打開『繳交概況』看到的是 180 個人混在一起，只能靠 Sheets 裡的名單一個一個搜尋。」

> 「我聽說 Moodle 有『指定評分者』的功能，可是我在設定頁找了很久都沒看到。後來才知道它藏在『全部評完才公佈』**下面**，要先把那個改成『是』才會出現。這兩個名字看起來根本沒關係。」

> 「老師把我們三個都設成可以改設定的身分，有一次另一位助教不小心在列表上按到『准許延期』……還好只是延期。成績和『刪除作業』放在同一個選單裡，我每次都很緊張。」

**一致性**

> 「一致性是最難的。我們的做法是：開始改之前先三個人一起改 3 份，叫『校準』，對一下每個面向給幾分。然後每個人改自己的時段。改完我會在 Sheets 算三個時段的平均和標準差，如果某一班平均高了 5 分以上，就要回頭看是不是那位助教比較鬆。」

> 「E3 其實有『評分規準』，可是要先在設定裡把評分方式切過去，再用網頁表單一格一格輸入 4×4 的文字。而且我們的 rubric 還會在校準後改，改了 E3 會不會把已經評過的弄亂，我不敢賭。所以 rubric 一直放在 Sheets。」

> 「最大的問題是，學生申訴時我要讓他看到『你在哪個面向拿幾級』。可是我們在 E3 上只填了總分和一段評語，rubric 的細項都在 Sheets 裡，學生看不到。」

**統一公布**

> 「上學期 B 班的助教改得比較快，直接在 E3 打分數，學生馬上就收到『你的作業已被評分』的通知。A 班的同學就跑去問：為什麼 B 班出來了我們還沒有？從那之後老師就規定：**全部改完、對過分數，同一天晚上 8 點一起公布**。」

> 「我們現在的做法很土：先在 Sheets 改，等三班都好了，指定一個人在公布當晚花兩個小時，把 180 個分數貼進 E3 的『快速評分』。評語就一個一個貼。」

> 「我不知道 E3 可以藏成績。『全部評完才公佈』這個名字我看得懂，可是它其實是一整套『評分中、待審、可發布、已發布』的流程，設定頁完全沒講，要點小問號才知道。」

**學生來信與申訴**

> 「公布那天晚上信箱會爆，大概會收到 30 到 40 封。有問『為什麼這麼低』的，有說『我們組的分工不公平』的，也有說『我有交但顯示沒交』的。」

> 「站內信最麻煩的是：三個時段的學生都寄給全部助教，或者只寄給老師，老師再轉給我們。**誰回了、誰沒回**，E3 上看不出來，我們要在 LINE 裡喊『這封我接了』。」

> 「回信前我要開三個分頁：信、那個學生的繳交、Sheets 的 rubric。在 Chromebook 上分頁一多就很卡。」

> 「我們規定申訴一週內要結案。可是 E3 的信沒有『已處理』的狀態，只有星號跟標籤。我試過用標籤，可是標籤只有我自己看得到，其他助教看不到。」

**Chromebook**

> 「Chromebook 沒辦法裝軟體。下載全部作業會變成一個 zip，要在『檔案』App 裡打開，裡面是一堆用學生名字命名的資料夾。PPTX 要轉成 Google 簡報才能看，很慢。我寧願直接在網頁上看 PDF。」

> 「E3 的表格在我的螢幕上很擠。『繳交概況』的狀態欄被擠到一個字一行，一個學生就佔掉半個螢幕。」

## 觀察紀錄

### 任務 A：找出「先藏成績、統一公布」和「分派評分者」的設定（作業設定頁，只看不存）

路徑：課程頁 → 期末報告 → 次導覽「設定」（`/course/modedit.php?update=218500`），共 2 次點擊，2.1 秒。要再點「展開全部」（第 3 次點擊）才會看到所有區段。

| 觀察 | 結果 |
| --- | --- |
| 頁面長度 | 展開後 4,707 px，等於 1366×768 螢幕的 **6.1 個螢幕高**。 |
| 「全部評完才公佈」的位置 | `id_markingworkflow`，在頁面 y≈3,320 px（約第 4.3 個螢幕），在「成績」區段的最後一列。這就是 Moodle 的 **marking workflow**，E3 把它翻成「全部評完才公佈」。 |
| 說明（點 ? 才看得到） | 「如果啟用此功能，在未發布給學生之前，分數會走完一系列工作流程。這麼一來即可分成多次評分，並可以同時將分數發布給所有學生。」 |
| 「指定評分者」 | `id_markingallocation` 存在，但目前是**隱藏的**（hideIf：要先把「全部評完才公佈」改成「是」才會出現）。說明是「此功能如果啟用，依工作流程，評分者可以被指派給特定學生(群)」。 |
| 「在匿名評分時允許部分釋出成績」 | 同樣是隱藏的。說明裡又把它叫做「彌封評閱」。 |
| 匿名受評 | 顯示成**純文字「否」**，已經鎖定。說明：「一旦此作業已經有人繳交或被評分了，則此匿名受評的設定將被鎖住。」 |
| 群組繳交作業 | 在「群組繳交作業設定」區段裡，同樣是**鎖定的純文字「否」**，因為已經有人繳交。「需依分組繳交」「小組所有成員都要繳」「指定集群」三個欄位隱藏。 |
| 評分方式 | 下拉選單：直接評分／給分指引／評分規準。 |
| 通知 | 「若有作業繳交，要通知評分者」否、「若有作業遲交，要通知評分者」否、**「"通知學生"的預設設定」是**。 |
| 提醒我評分截止日期 | 有設定，用途只是「放在焦點綜覽上來提醒教師」，學生看不到，也不會影響公布時間。 |
| 群組模式 | 沒有分組／分隔群組／可視群組。「集群」只有「無」可選。 |

**困惑點**

1. 「全部評完才公佈」聽起來像一個開關，其實是一整套狀態機：未評分 → 評分中 → 評分完成 → 審閱中 → 可發布 → 已發布。
2. 「指定評分者」完全看不到。小雅這種想找「分派」的人，在這頁找不到任何線索。
3. 用詞不一致：群組、小組、分組、集群混用；群組模式的選項是「分隔群組／可視群組」，說明裡卻寫「彼此隔離的小組／彼此可見的小組」；匿名的部分有「匿名受評」「匿名評分」「彌封評閱」三種說法。
4. 「群組繳交」和「匿名」**一旦有人繳交就不能改**。如果開學時沒設好，分組報告就只能「一人一列」逐一評分。

**另一條「先藏成績」的路（成績簿設定）**：`/grade/edit/tree/index.php?id=23571`，1.5 秒。每個評分項目的「動作」選單有「編輯評分項目／隱藏／鎖定」。作業頁不會連到這裡，必須從側欄「成績管理」或「檢視成績單」繞過去。在 Moodle 的標準行為裡，把評分項目設成隱藏，學生就看不到分數和回饋。但如果評分時「通知學生」有勾，學生**還是會收到「已評分」的通知**（未實測）。這正是小雅上學期遇到的狀況。

### 任務 B：繳交概況（評分表）的篩選與批次操作

`/mod/assign/view.php?id=218500&action=grading`，1.6 秒。

- **篩選列**：搜尋用戶、依名稱篩選（姓／名字首）、狀態、進階。
  - 狀態的選項：全部、尚未繳交、草稿、已繳交、需要評分、授予的擴展。
  - 進階只有「包含已停權的課程成員」一項。
- **沒有群組選單**，因為作業的群組模式是「沒有分組」（`core_group_get_activity_groupmode` 回傳 0）。
- **沒有「評分者」和「工作流程狀態」篩選**，因為兩個功能都沒開。Moodle 4.5 開啟後會在篩選列多出「評分者」和「工作流程」兩個選單（未實測）。
- **表格寬度**：14 欄，表格的 scrollWidth 是 1,638 px，比 1366 寬的螢幕扣掉側欄後的可用寬度大很多，所以要水平捲動。
  - 學號和電子郵件兩欄佔掉約 400 px。
  - 「狀態」欄被擠到**一個字一行**，「未繳交／已經超過應繳交時間: 136 日…」一列就高約 330 px，**一個螢幕只放得下 2 位學生**（截圖 `23-grading-bulk.png`）。
- **批次操作**：勾選學生後，底部會出現固定列，有「鎖定作業／解除鎖定作業／下載／刪除／更多」，「更多」裡是「**延伸**」（Extension 的誤譯，應該是延期）和「**Upload feedback**」（沒有翻譯）。工作流程沒開時，沒有「設定評分工作流程狀態」和「分派評分者」這兩個批次動作。
- **每一列的選單**：「防止作業更改／准許延期／刪除作業」和「成績」按鈕放在一起，小雅在訪談裡提到的誤觸風險就在這裡。
- 「動作」選單：檢視成績單、以一個壓縮檔上傳多個回饋檔案、下載全部繳交的作業。

### 任務 C：單一評分頁（部分觀察）

`action=grader`，1.4 秒後跳出錯誤，原因見上方的限制說明。從外框可以看到：

- 「通知學生」**預設是勾選的**，對應作業設定裡的「"通知學生"的預設設定：是」。如果沒開工作流程，存檔就會通知學生。
- 「儲存後顯示下一位」可以連續評分，但順序是表格的排序和篩選，**不能限定「只看我負責的 60 人」**，除非開了指定評分者或群組。
- 「進階評分」分頁（`/grade/grading/manage.php?...area=submissions`，1.6 秒）只有一個「改變啟用的評分方式為［直接評分］」下拉選單。要先切換方式並存檔，才能開始定義 rubric。沒有匯入 rubric 的入口。

### 任務 D：成員、分組、依群組評分

**成員**（`/user/index.php?id=23571`，1.6 秒）

- 共 37 位參與者，分 2 頁顯示（`core_enrol_get_enrolled_users` 的角色統計：學生 26、旁聽生 6、教師 4、助教 1）。
- 篩選類別：關鍵字、狀態、角色、選課方式、未活動超過。**沒有「群組」篩選**，因為課程沒有群組。
- 角色下拉選單有「沒有角色、教師、一般助教、高階助教、學生、旁聽生、學分班學生、學藝」。
- 「分組」欄每個人都是「沒有分組」。
- 勾選後的「針對選取的使用者…」有：新增一則筆記、匯出（CSV／XLSX／HTML／JSON／ODS／PDF）、編輯選課。另外還有一個獨立的「**給選擇的使用者發送一封郵件…**（收件人／副本／密件副本）」，這是 dcpcmail 的入口，可以一次寄信給一群勾選的學生。

**分組管理**（側欄「分組管理」→ `/group/index.php?id=23571`，1.9 秒）

- 左邊「分組」、右邊「成員：」兩個空的列表框，下方標題「**將被選出的**」是沒翻完整的字串（原文是「Selected group: …」）。
- 按鈕：顯示群組中的各成員、修改群組設定、刪除被選出的群組、建立群組、自動建立群組、新增/移除 用戶。
- 集群（`/group/groupings.php`）只有「建立集群」。
- 概覽（`/group/overview.php`）可以把分組下載成 CSV／XLSX／JSON／ODS／PDF。

**自動建立群組表單**（只看，沒有按「預覽」或「送出」，1.5 秒）

- 依據：群組數／成員數。
- 角色：所有、教師、高階助教、學生、旁聽生、同步選課管理員。
- 分配方式：尚未分配、隨機、依姓名、**依所屬系所**、依學號。
- 另有命名規則、防止最後的小群組、忽視已在群組中的使用者、只包含活動選課者，以及「自動建立的小組集群」。
- 可以用來建「時段 A／B／C」，但時段資料不在 E3 裡（三個時段是併班進來的），只能手動加，或用 CSV 匯入群組。

**依群組評分**（未實測）

- 有開「群組繳交作業」時，評分頁會有「套用到整個群組」，一組評一次。
- 沒開時，只能把群組模式設成「分隔群組」，用評分表的群組選單篩出一組 5 人，再一人一列輸入。

依照目前作業的鎖定狀態，期末報告**已經不能**改成群組繳交。

### 任務 E：E3 站內信（我的郵件）

入口有兩個：

- 頁首的使用者選單 →「我的郵件」（`/local/dcpcmail/view.php?t=inbox&c=1`，全部課程，1.8 秒）。
- 課程側欄 →「我的郵件」（`?c=23571&t=inbox`，只顯示這門課）。這一頁第一次載入花了 **13.8 秒**，是這次所有量測裡最慢的。

觀察到的介面：

- **資料夾按鈕**：建立新郵件、收件夾、草稿夾、寄件備份、垃圾桶。麵包屑會顯示未讀數「我的郵件 (4) / 收件夾 (4)」。
- **工具列**：
  - 勾選選單：所有／空／讀／未讀／重要郵件／未標識重要郵件。
  - 標籤、刪除。
  - 更多：標識為已讀／未讀／重要／非重點、編輯標籤、移除標籤。
  - 搜尋：關鍵字、寄件人、收件人、只顯示未讀、有附件。
- **每列**：☐、☆、寄件人（系所 / 姓名）、**課程簡稱標籤**、主旨、日期。沒有內文摘要，**沒有「已回覆」標示**，也沒有指派欄位。
- 每頁筆數的連結（5／10／20／50／100）帶 sesskey，點下去會改偏好設定，所以沒有點。
- 這門課的收件夾目前 1 封，全部課程的收件夾第 1 頁 20 封，涵蓋很多門課。內容沒有開啟，也不記錄。
- **API**：網站有開 `local_dcpcmail_get_unread_count / get_menu / get_index / search_index / get_message / set_unread`（EM3 學生版已經在用）。
  - `get_menu` 會回傳每門課的未讀數和標籤。
  - `get_index type=course itemid=<courseid>` 可以列出單一課程的信，欄位有 `sender, recipients, subject, time, unread, starred, labels, attachments`。
  - **沒有寄信、回信、設定標籤或星號的 API**。

小雅的「誰接這封信」需求，E3 完全沒有對應功能。標籤是個人的，其他助教看不到。

## 痛點（依嚴重度排序）

1. **「統一公布」的功能存在，但名字和位置都不對。** 工作流程被譯成「全部評完才公佈」，藏在設定頁第 4 個螢幕的最後一列，說明要點問號才看得到。不開的話，「通知學生」預設會勾，每存一次成績就通知一次學生，時段之間馬上就有落差。結果助教只好把分數全部放在 Sheets，公布當晚再花 2 小時手動貼 180 筆。
2. **E3 不知道「誰改誰」。** 「指定評分者」要先開工作流程才看得到；課程沒有群組；評分表沒有「只看我的」篩選。三位助教各自在 180 人的列表裡搜尋。
3. **rubric 細項不在 E3 上，申訴時拿不出來。** 評分規準要先切換評分方式並存檔才能定義，校準後又常常要改，所以留在 Sheets。學生只看得到總分和一段評語，申訴時助教要另外整理。
4. **申訴信沒有分派和狀態。** 站內信沒有「已回覆」和「誰負責」，標籤又只有自己看得到。三位助教只能在 LINE 協調，容易漏回或重複回。回一封信要開「信、繳交、Sheets」三個分頁，課程收件夾還可能要等 13.8 秒。
5. **群組相關設定一旦有人繳交就鎖死。** 「群組繳交作業」和「匿名受評」在學生交件後就不能改，學期中才發現要依組評分時已經來不及了。用詞（群組／小組／分組／集群）也讓人搞不清楚該設哪一個。
6. **評分表在 Chromebook 螢幕上幾乎不能用。** 14 欄、1,638 px 寬，狀態欄一字一行，一個螢幕只放 2 位學生；危險動作（刪除作業、准許延期）和成績放在同一個選單；批次選單有「延伸」「Upload feedback」這類誤譯或沒翻的字。
7. **Chromebook 下載後很難處理。** zip 要在「檔案」App 裡解開，PPTX 要轉檔。小雅寧願在線上看 PDF，不想「下載改完再上傳」。

## 需求

**Must**

- M1：**依評分者或時段切出「我的清單」**。我負責的學生和組別、各自的繳交狀態、我改了幾份。
- M2：**先改、晚公布**。存分數時不要通知學生，到指定時間或三位助教都確認後，一鍵讓三個時段同時公布。
- M3：**rubric 評分面板**。點選每個面向的等級後自動算總分，並把「面向：等級＋一句說明」寫進給學生的評語，申訴時直接看得到。
- M4：**從 Sheets 貼上或匯入一整欄分數和評語**，先預覽對應結果和差異，再一次寫入。

**Should**

- S1：**一致性儀表板**。按評分者（時段）顯示平均、標準差和分布，以及各 rubric 面向的平均，校準時用。
- S2：**課程信箱的「申訴」視圖**。只顯示這門課的信，並在旁邊附上寄件學生的繳交、分數和 rubric 細項，用一個畫面就能回信。
- S3：**依組評分**。選一組、給一個分數，套用到全組，再個別微調。
- S4：學期初提醒：「這份作業要分組評分或匿名嗎？學生交件後就不能改了。」

**Could**

- C1：申訴的「誰接了」與處理狀態，在助教之間共享。
- C2：以 PDF 線上預覽作業，取代下載 zip。
- C3：批改時不要顯示學號和 email 欄，讓表格在 1366 寬的螢幕也能一列一位。

## 對朋友假說的判定

朋友原話：「我想要可以在介面上新增、編輯各種教材：Markdown 編輯、新增不同的文件、建立小考、評分很重要——我最常用評分。我需要把大家的作業下載下來，改完再上傳回去。」

| 假說 | 小雅的反應 | 判定 |
| --- | --- | --- |
| Markdown 編輯教材 | 「教材是老師放的，我們不碰。」 | **不適用**於這類助教。 |
| 新增不同的文件 | 只有偶爾幫老師放評分說明 PDF。 | **低**。 |
| 建立小考 | 通識課沒有小考。 | **不適用**。 |
| **評分很重要、最常用評分** | 「完全同意，學期後半我 80% 的 E3 時間都在評分和回申訴信。」 | **強烈成立**，但重點不是「填分數」，而是**分工、一致性和統一公布**：誰改誰、rubric、先藏後放。 |
| 下載作業，改完再上傳 | 「我不會在檔案上批註，我是在 Sheets 打 rubric 分數，最後貼回 E3。Chromebook 處理 zip 很痛苦。」 | **部分成立**。「改完再上傳」對她而言是**把試算表的分數和評語批次寫回 E3**，不是上傳批註檔。批註 PDF 和回饋檔只有少數助教會用。 |

**功能排序**（小雅的優先順序，1 最重要）：

1. 先改、晚公布（工作流程與統一發布）
2. 依評分者或時段切出「我的清單」
3. rubric 評分面板（評語自動帶入細項）
4. 從 Sheets 貼上或匯入分數
5. 一致性儀表板
6. 課程信箱的申訴視圖
7. 依組評分（套用到整組）
8. 下載作業 zip／上傳回饋檔
9. 新增文件
10. Markdown 教材編輯
11. 建立小考

## EM3 功能提案（依優先度排序）

### 1. 「公布」模式：先藏、再同時發布

- **做法**：EM3 偵測作業的 `markingworkflow`（`mod_assign_get_assignments` 有這個欄位）。
  - **已開**：評分時一律用 `mod_assign_save_grade(s)` 搭配 `workflowstate=inmarking` 或 `readyforrelease` 存檔。頁面頂端顯示「已評 142／180，待發布 142」。按下「發布」時，對選取的學生呼叫 `mod_assign_set_user_flags`（`workflowstate=released`），可以依時段分批，但用同一個按鈕送出。
  - **沒開**：顯示警告「現在存分數，學生會立刻看到並收到通知」，並提供**直接開到 E3 設定頁「成績」區段**的連結（`/course/modedit.php?update=<cmid>#id_modstandardgrade`），說明要把「全部評完才公佈」改成「是」。
- **API**：`mod_assign_save_grade`、`mod_assign_save_grades`（都有 `workflowstate` 參數）、`mod_assign_set_user_flags`、`mod_assign_get_user_flags`都存在。
  - 開啟工作流程這項設定**沒有 API**，只能交給 E3 處理。
  - 開了工作流程之後，Moodle 只在狀態變成「已發布」時才寄通知給學生（Moodle 標準行為，未實測）。
  - 沒開工作流程時，用 API 存分數會不會寄通知，**需要用測試作業確認**。

### 2. 「我的清單」：依評分者或時段分工

- **做法**：作業頁加一個「評分者」切換：全部、我、其他助教。
  - 有開「指定評分者」時，清單的依據是 `allocatedmarker`（`mod_assign_get_user_flags`）。批次分派用 `mod_assign_set_user_flags allocatedmarker=<userid>`，可以「把時段 A 群組的人全部分給小雅」。
  - 沒開時，退而使用群組：`core_group_get_course_groups` 加上 `mod_assign_list_participants groupid=<id>`，或 `core_group_get_course_user_groups`。
  - 兩者都沒有時，提示「到 E3 建立時段群組」，並附上 `/group/autogroup.php?courseid=…` 或群組匯入頁的連結。
- **API**：讀取和分派都可以做。可選的評分者名單用 `core_enrol_get_enrolled_users` 篩出教師、一般助教、高階助教。開啟「指定評分者」和建立群組都**沒有 API**，只能交給 E3 處理。

### 3. rubric 評分面板（EM3 端的 rubric）

- **做法**：rubric 定義在 EM3，可以從 Sheets 貼上 4×4 表格，存成 JSON，匯出後分享給其他助教。評分時點選等級，系統算出總分，並產生結構化的評語，例如「論點：3/4 — …；證據：2/4 — …」。用 `mod_assign_save_grade` 寫入 `grade` 和 `plugindata.assignfeedbackcomments_editor`。
- **為什麼不用 E3 的評分規準**：
  - 這個網站**沒有** `core_grading_get_definitions`，EM3 讀不到 E3 rubric 的 criterion 和 level ID，也就無法填 `advancedgradingdata`。
  - E3 定義 rubric 必須在網頁上切換評分方式並存檔。
  - 把細項寫進評語，學生在 E3 上也看得到，申訴時直接就有依據。
- **同步**：EM3 是純靜態 SPA，沒有後端，三位助教之間的 rubric 只能靠匯出、匯入 JSON 同步。每個 rubric 有版本號，評語裡附上版本號，避免校準後混用不同版本。

### 4. 從 Sheets 貼上分數與評語

- **做法**：在作業頁貼上 Sheets 的兩到三欄（學號、分數、評語）。EM3 用學號對應 `mod_assign_list_participants`，顯示預覽和差異（新增、變更、空白、找不到的學號）。確認後用 `mod_assign_save_grades` 一次寫入，可以搭配提案 1，一律存成「待發布」。也可以反過來，把目前分數匯出成可以貼進 Sheets 的 TSV。
- **API**：可行。`save_grades` 本來就是批次 API。E3 的 `/grade/import/csv` 也可以當備案，只能交給 E3 處理。

### 5. 一致性儀表板

- **做法**：依評分者（`allocatedmarker`）或群組，顯示分數的平均、標準差、分布。如果用了提案 3 的結構化評語，再加上各面向的平均。某一組偏差超過門檻時就標示出來。
- **API**：
  - 分數用 `mod_assign_get_grades`，裡面有 `grader` 欄位，沒開「指定評分者」時也能依「實際評分者」分組。
  - 評語要用 `mod_assign_get_submission_status`（帶 userid）逐人讀取，180 人可以用 `tool_mobile_call_external_functions` 合併成幾次請求。
  - 全部都在本機計算，**不會寫入任何東西**。

### 6. 課程信箱的「申訴」視圖（唯讀＋交給 E3 回信）

- **做法**：在課程頁加上「來信」分頁，用 `local_dcpcmail_get_index type=course itemid=<courseid>` 只列這門課的信。點開一封信時，右側帶出這位寄件人在本課各作業的繳交狀態、分數和 rubric 細項（提案 3 的評語），讓助教一眼看完。「回覆」按鈕直接開 E3 的 `/local/dcpcmail/view.php?t=inbox&m=<id>`。
- 「誰接了」只能在 EM3 本機用星號或本地標記，並清楚說明**其他助教看不到**。
- **API**：讀信可以做（EM3 學生版已經在用），`set_unread` 也可以。**寄信、回信、標籤、星號都沒有 API**，只能交給 E3。另外要注意 `get_message` 可能會把信標成已讀，打開前要明白告訴使用者。

### 7. 依組評分

- **做法**：
  - 作業有開群組繳交時，用 `mod_assign_save_grade applytoall=1`，評一次就套用到全組。
  - 沒開時，在「我的清單」裡依群組分組顯示，提供「全組給同分」：先產生 5 筆，再用 `mod_assign_save_grades` 寫入，寫入前可以逐人微調。
  - 學期初建立作業時，提醒「群組繳交和匿名在學生交件後會鎖定」，並附上 E3 設定頁的連結。
- **API**：給分可以做。群組繳交這項設定**沒有 API**，只能交給 E3 處理。

### 8. 適合 Chromebook 的評分畫面（搭配提案 1–4）

- 一列一位學生，預設不顯示學號和 email。
- PDF 在右側面板預覽（沿用學生版的 blob 預覽）。
- rubric 面板固定在畫面底部。
- 「刪除作業」「准許延期」這類危險動作移到二級選單，並加上確認步驟。
- **不做**「下載 zip → 改 → 上傳 zip」的流程。上傳回饋檔（`files_filemanager` 加上 `/webservice/upload.php`）留給少數需要批註 PDF 的課程，優先度最低。

### 不建議在這類助教的版本裡做

Markdown 教材編輯、新增文件、建立小考：這類助教不負責教材，而且建立和編輯 module 也沒有 API。
