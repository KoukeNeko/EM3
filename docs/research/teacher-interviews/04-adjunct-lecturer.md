# 教師訪談 04：護理學系兼任講師「張老師」

> 研究方式：研究者扮演受訪者，用真實的 `editingteacher` 帳號（課程 23571，26 位學員，只有一個「一般」區段）以 Playwright 操作 E3。手機為 412×915（isMobile、hasTouch），平板為 1024×1366（isMobile、hasTouch），對照用電腦 1440×900。全程透過 `scripts/e3-browser.mjs`，非 GET 請求一律擋下，帶 `sesskey` 的 GET 也會擋。整個過程沒有發文、上傳、評分、寄信，也沒有切換編輯模式或變更設定。名單數字用唯讀 API `mod_assign_list_participants`／`mod_assign_get_submissions` 對照。研究日期：2026-10-15。截圖在 scratchpad `ti-04/`（`m*` 是手機、`t*` 是平板、`g*` 是評分器），因為拍到學生姓名、帳號與繳交內容，沒有複製進 repo。報告裡不寫任何學生姓名、學號、信箱、繳交內容或分數。
>
> 張老師實際任教的「基本護理學實驗」並不在這個帳號裡，所以她的任務都改在課程 23571 上做：「期末報告」代替「實驗心得」，「公告」討論區代替她的實驗課公告。

## 一、訪談重點

### 她在 E3 上做什麼，在 LINE 上做什麼

| 事情                       | 現在在哪裡做                       | 原因（她的說法）                                                                  |
| -------------------------- | ---------------------------------- | --------------------------------------------------------------------------------- |
| 上傳 PPT                   | E3，**請助教或系辦幫忙**           | 「規定教材要放 E3。我自己放過一次，放完找不到，以為沒成功又放了一次，結果兩份。」 |
| 提醒明天要帶什麼           | **LINE 群組**，拍一張物品照片      | 「LINE 打一句話、拍一張照，十秒。E3 我不知道學生會不會收到。」                    |
| 看誰沒交心得               | E3 列表看一眼，**再到 LINE 點名**  | 「列表要左右滑，名字擠在一起，我都截圖放大看。」                                  |
| 打分數加評語               | 紙本或 Excel，學期末請助教一次輸入 | 「我會在心得上寫『觀察很仔細，下次注意無菌區』，可是 E3 那格太小了。」            |
| 分組、請假、臨時改實驗內容 | LINE                               | 「急的事一定是 LINE。」                                                           |

> 「E3 對我來說是『交差』用的：講義要放、成績要登。真的跟學生講話是 LINE。」

### 讓她放棄的時刻

1. **看不懂的字。** 「什麼『整包教材檔案』、『顯示的期間』、『活動完成條件』，我不知道那是什麼，也不敢亂按，怕按了學生就看不到。」看到英文（例如公告列表上的 `Timed` 標籤）她就會停下來。
2. **找不到入口。** 「手機上最上面只有一個開關、一個鈴鐺，三條線在哪裡？左邊那個小圓圈裡面才有東西，我是後來才知道的。」
3. **按完不知道有沒有成功。** 「放完講義跳回課程首頁，我的東西在最下面，要滑才看得到，第一次我以為沒放上去。」
4. **字太小、按鈕太小。** 「我戴老花眼鏡也很難點到那個加號。」
5. **要打很多字。** 「我用語音講一段話，它變成一大段沒有標點的字，要再改。標題一定要填，我又要想一個標題。」

### 對評語和分數的期待

> 「實驗心得就是 0 到 10 分，或甲乙丙。我想要按一個數字，然後講一句話，像『步驟正確，記得洗手時間要夠』，送出，下一個。不要讓我看到一整張表。」
>
> 「我有幾句話每個學期都在講，如果可以選就好了。」

### 對「未交的人」的期待

> 「我要的就是『這 8 個人還沒交』，然後一個按鈕『提醒他們』。不要讓全班都收到，交了的人會覺得被罵。」
>
> 「如果 E3 沒辦法寄，給我一串名字讓我複製到 LINE 也可以，我在 LINE 群組 @ 他們。」

| 8 | 中 | **手機討論區列表**：標題被擠成一個字一行，看不出發了什麼 | `m02-forum-full` |
| 9 | 低 | 通知的預設值不一致：公告的「立即發送通知」預設不勾，評分的「通知學生」預設勾選，她不知道學生到底會不會收到 | 任務 A 步驟 10、任務 D |
| 10 | 低 | 每一頁 1.5–3 秒，評分器 4 秒；一個流程要換 5–7 頁 | 各任務耗時 |

## 四、需求

### 必須（Must）

1. **手機一頁發公告**：內文大字輸入框（可以用語音），主旨可以留空（自動取內文第一句），一顆「拍照／選照片」大按鈕，送出前明確告訴她「全班 N 人會收到 Email」。
2. **「誰還沒交」的正確名單**：以目前的學員為準，顯示人數和名字，不會跟 E3 一樣算錯。
3. **只對沒交的人提醒**，或至少能一鍵複製名單貼到 LINE。
4. **手機評分卡**：一次一個學生，繳交內容放大顯示，大的分數按鈕或數字鍵盤，一句評語（可語音、可選常用句），按「送出並下一位」。
5. **全中文、大按鈕（≥44 px）**，不出現技術錯誤訊息。

### 應該（Should）

6. **上傳後明確回報位置**：「已放在『課程講義』，學生在 EM3 的『教材』分頁最上面會看到」，並附連結。
7. **常用評語片語庫**（每學期都會講的話），存在本機，可以匯出、匯入。
8. 公告範本：「明天實驗課請攜帶：＿＿」，內含勾選清單（護理服、名牌、聽診器……）。
9. 一眼看到每份作業的進度：「已交 18／26，已評 0」。

### 可以（Could）

10. 大字模式／放大字級設定。
11. 評語語音輸入完自動補標點。
12. 「上次發的公告」一鍵複製再改。

## 五、對朋友假設的判斷

| 假設 | 張老師的反應 | 判斷 |
| --- | --- | --- |
| 介面上新增、編輯各種教材 | 「我只要放 PPT，而且要知道放到哪裡。其他的我不會用。」 | **部分成立**。她要的只是「上傳一份檔案」，最在意的是上傳後能確認位置，不是很多種教材類型。而且 API 不能建立模組，只能交給 E3 處理，再由 EM3 確認結果 |
| Markdown 編輯 | 「Markdown 是什麼？」 | **不成立**（對這類老師）。她要的是語音和拍照，純文字加照片就夠了。Markdown 應該只是進階選項 |
| 新增不同的文件 | 「PPT 跟 PDF，就這樣。」 | **弱**。檔案上傳要有，種類多不重要 |
| 建立小考 | 「實驗課是現場技術考，用評分表，不考選擇題。」 | **不成立**（對她）。這門課的評量是在現場做的 |
| 評分很重要，最常用 | 「很重要，但我一學期只改幾次心得。我要的是快，不是功能多。」 | **成立，但要換個方向**。重點不在功能多，而在「手機上一個分數加一句評語」，30 秒內完成一個人 |
| 下載全部作業，改完再上傳回去 | 「我不會在檔案上改，我是看完寫一句話。」 | **不成立**（對她）。她不需要批次下載和上傳回饋檔；這比較像助教或理工科的工作流程（E3 的「動作」選單裡已經有「下載全部繳交的作業」和「以一個壓縮檔上傳多個回饋檔案」） |

## 六、教師功能優先順序（張老師的觀點）

1. **未交名單＋只提醒他們**（含複製給 LINE）
2. **手機發公告＋附照片**
3. **手機評分卡：分數＋一句評語＋常用句**
4. **上傳 PPT 後確認位置**（交給 E3 上傳，回 EM3 確認）
5. 作業進度一覽（已交／已評）
6. 片語庫、公告範本
7. （她用不到）Markdown 編輯器、建立小考、題庫匯入、批次下載與上傳回饋檔

## 七、EM3 功能提案與 API 可行性

| # | 提案 | 做法 | API 可行性 |
| --- | --- | --- | --- |
| P1 | **作業進度＋未交名單** | 課程頁「作業」分頁，每份作業顯示「已交 18／26・未交 8・待評 18」。點「未交 8」展開名單（只列目前的學員）。若跟 E3 的數字不一樣，就說明「有 4 份來自已退選的學生」 | **可行**：`mod_assign_list_participants`（`submitted`、`requiregrading`）＋`mod_assign_get_submissions`。名單只在畫面上顯示，不快取到 localStorage |
| P2 | **提醒沒交的人** | 三個選項：(a)「複製名單」，產生「@〈學生A〉@〈學生B〉… 期末報告還沒交，請在 ○○ 前補交」，直接貼到 LINE；(b)「發公告給全班」並預填內容（會提醒她「全班都會收到」）；(c)「在 E3 寄信」：開 E3 的「成員」頁並說明要勾哪幾個人 | (a) 純前端；(b) `mod_forum_add_discussion`；(c) 沒有 E3 郵件的 API，`create.php` 又要 sesskey，只能開新分頁交給 E3。**沒辦法做到真正只寄給部分學生的站內通知** |
| P3 | **手機快速公告** | 單一畫面：大的內文框（原生 textarea，支援語音和注音）、主旨可空白（自動取第一句）、「拍照／相簿」大按鈕（`<input type=file accept="image/*" capture>`）、範本按鈕「明天實驗課請帶…」。送出前的確認視窗寫「26 位學生會收到 Email」，並讓她選要不要立即寄出 | **可行**：照片先用 `/webservice/upload.php` 上傳到草稿區，再用 `mod_forum_add_discussion` 帶 `options[attachmentsid]`。「立即寄出」和「顯示期間」對應的 option 要再確認 4.5 的參數；確認前就照 E3 預設，並在介面上說明會延遲寄出 |
| P4 | **手機評分卡** | 一次一位：上方是繳交內容（線上文字直接顯示、檔案用預覽），下方是大的分數按鈕（依滿分產生 0–10 或 10 分一級，也可以自己輸入），評語框（可語音）＋片語晶片（常用句存在 `em3:prefs`），「送出並下一位」。只列「待評分」的人，評分器停在哪一位以本機為準 | **可行**：`mod_assign_save_grade`（`grade`、`attemptnumber=-1`、`addattempt=0`、`workflowstate=""`、`applytoall=1`、`plugindata[assignfeedbackcomments_editor][text/format]`）。「通知學生」做成明確的開關。送出前顯示「〈學生A〉：8 分＋評語」確認 |
| P5 | **上傳 PPT：交給 E3，回到 EM3 確認** | EM3 的「新增教材」按鈕直接開 E3 的 `modedit.php?add=resource&course=…&section=…`（只開一條路，不要讓她在兩條路之間選），旁邊附三行中文說明：「填名稱 → 按＋上傳 → 按『儲存並返回課程』」。回到 EM3 後，用 `core_course_get_contents` 比對前後差異，顯示「剛剛新增：〈檔名〉，學生在『教材』分頁最上面看得到」；如果是「暫存為草稿」的狀態，就用大字提醒她學生看不到 | **建立不可行**（沒有建立模組的 API），**確認可行**（`core_course_get_contents` 的 `visible`、`uservisible`、`modname`） |
| P6 | **教師模式的無障礙基準** | 觸控目標至少 44×44，教師畫面字級預設 18 px，只用中文，錯誤訊息翻成人話（「網路不穩，剛剛的內容還在，請再按一次」），表單送出前把草稿存在本機 | 純前端 |

### 不建議優先做的（對這類使用者）

- Markdown 編輯器、建立小考、GIFT 題庫匯入：她用不到。給其他類型的老師當進階功能就好。
- 批次下載、上傳回饋檔：E3 已經有，她也用不到。

## 附註：研究限制

- 這門課是 React 微學分，不是護理實驗課。學生人數 26（她的課是 40），作業設定也不一樣（線上文字＋回饋評語／檔案／PDF 註記）。
- 評分器在唯讀環境下會因為偏好設定的 POST 被擋而停在載入中，所以沒有看到評分欄和評語欄本身，任務 D 的表單內容是依作業設定推估的。
- 公告附照片的上傳步驟 7–9 沒有實際執行；檔案挑選器的清單 AJAX 也被擋，沒有看到「上傳一個檔案」面板的內容。
- 公告訊息欄是純文字框，這可能是這個帳號的編輯器偏好造成的。如果其他帳號用的是 TinyMCE，輸入法與插圖的結論會不一樣。
