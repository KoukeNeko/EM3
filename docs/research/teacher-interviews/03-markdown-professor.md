2026-10-15 進行。訪談對象是模擬的人物，所有引言都是依人物設定寫的，不是真人發言。觀察部分是用真實的 editingteacher 帳號，以唯讀瀏覽器（`scripts/e3-browser.mjs`）和唯讀 API（`scripts/e3-ws.py`）在課程 23571 實際操作 E3。全程沒有送出任何表單，也沒有存檔、匯入、評分或上傳。截圖與 DOM 只留在 scratchpad，沒有放進 repo。

## 訪談重點

**每週的備課流程**

> 「我教材都是在 repo 裡寫 `weekN/README.md`，裡面有 C 的程式碼區塊，也有 `$\tau = RC$` 這種式子。寫好 push 上去，GitHub 就渲染好了。問題是學校要求作業和成績要在 E3，我每週都得把同一份東西再搬一次進 E3。」

> 「搬的方式現在是：在 VS Code 用 pandoc 轉成 HTML，打開 E3 那個編輯器，找到原始碼按鈕，貼進去，再祈禱它不要把我的 `<pre>` 吃掉。數學式我到現在都不確定 E3 會不會渲染，所以乾脆截圖貼上去。」

> 「我最怕的是那種所見即所得的編輯器。按 Tab 不是縮排、是跳到下一個欄位；貼程式碼會被自動換成彎引號；空白被吃掉。程式碼一旦被改壞，學生照抄就編譯不過。」

**評分流程**

> 「程式作業我根本不會在 E3 上一個一個改。我是 GitHub Classroom 收作業，autograder 跑完會有一個 CSV，`student_id,score,feedback`。我要的就是把這個 CSV 丟進去，分數和評語就到每個學生身上。」

> 「如果 E3 那邊是用作業繳交，我會用『下載全部繳交的作業』拿 zip，丟進我的測試腳本，跑完一樣產 CSV。我不需要一個漂亮的評分畫面，我需要一個可靠的匯入。」

> 「但我很在意的是：匯入要用學號對。CSV 裡我只有學號，我不會有學生的 Moodle 內部 ID，也不一定有 email。」

**隨堂小考**

> 「小考五題，四題選擇一題簡答。我在 LaTeX 裡已經有題庫了。如果 E3 可以吃某種純文字格式，我寫個小腳本轉一下就好。要我在網頁上一題一題點，我寧可紙本考。」

> 「我知道 Moodle 有 GIFT，研究所的時候助教用過。那東西基本上就是純文字，`::題名:: 題目 { =對 ~錯 ~錯 }`，對我來說剛剛好。」

**對 EM3 的期待**

> 「我不需要另一個編輯器。我需要的是：我在自己的地方寫，它幫我把格式變成 E3 吃得下的東西，然後把我帶到 E3 正確的那一頁，讓我少點十次滑鼠。」

> 「如果做不到直接建立教材，那至少告訴我『這份 HTML 已經複製了，下一步按這裡』。比起假裝能做到、結果卡在半路，我比較喜歡老實的交接。」

## 觀察紀錄

時間以 Playwright 的 `load` 事件計算。E3 頁面的 `load` 大多在 0.4–0.9 秒，但表單要等 TinyMCE 和 YUI 載完，實際可操作約 1.5–2 秒。

**關於 TinyMCE 沒有出現在截圖裡。** 研究用的唯讀瀏覽器會擋下 `service-nologin.php?info=N-method-calls` 這種看不出函式名稱的批次 AJAX，TinyMCE 載字串時會用到它，所以截圖裡的編輯器只剩純文字框。編輯器種類和外掛是從頁面上的 `Tiny.configureDefaultEditor(...)` 設定讀出來的，不是看畫面判斷的。

### 任務 2：寫一頁含程式碼與數學式的教材（`add=page`）

| 步驟 | 動作 | 觀察 |
| --- | --- | --- |
| 1 | 開 `/course/modedit.php?add=page&course=23571&section=0` | 標題是「新增 線上編輯文件」。E3 把 Moodle 的 `page` 改名成「線上編輯文件」，老師在活動選單裡要知道這個名字才找得到 |
| 2 | 看表單 | 26 個可填欄位，預設展開的 8 個。兩個富文字欄位：「說明」與「內容」。必填只有名稱和內容。其餘 4 個區段收合 |
| 3 | 找 Markdown 選項 | **沒有。** `page[format]` 和 `introeditor[format]` 都是隱藏欄位，值固定為 `1`（HTML） |
| 4 | 看編輯器 | TinyMCE 6。外掛有 `codesample`（插入程式碼區塊）、`code`（原始碼檢視）、`tiny_equation`（方程式編輯器）、`tiny_wiris`（MathType）、`tiny_wordimport`（匯入 Word）、`tiny_html`、`tiny_autosave` 等 |
| 5 | 看數學式渲染 | MathJax 篩選器在課程裡啟用（`/filter/manage.php` 顯示 MathJax、TeX 標記法都是「預設開啟」）。E3 的 MathJax 設定把 `$…$` 也當成行內數學式（Moodle 預設只有 `\(…\)`），`$$…$$` 是區塊數學式 |
| 6 | 看編輯器偏好 `/user/editor.php` | 可選「預設編輯器 / TinyMCE / Atto / 純文字區域」。依 Moodle 原始碼，改成「純文字區域」後，表單會出現文字格式下拉選單，其中有 Markdown。**這個偏好是全帳號的，我們沒有存，所以沒有實際驗證** |
| 7 | 版面 | 1440 寬的視窗下，左側抽屜蓋住表單的標籤欄（「線上編輯文件內容」只剩「內容」，標題被切掉） |

結論：

- **數學式會渲染**，而且支援 `$…$`。對黃老師來說，這是好消息：他 Markdown 裡的式子原樣放進 HTML 就會被 MathJax 處理，不需要截圖。
- **程式碼區塊做得到，但要靠 TinyMCE 的「插入程式碼」對話框或原始碼檢視**。直接貼進所見即所得的區域，縮排和引號有被改掉的風險。
- **Markdown 只能透過「純文字區域」偏好間接取得**。代價是：這個設定影響所有表單（包括作業評語）；Moodle 的 Markdown 是 PHP Markdown Extra，會先轉 Markdown 再跑 MathJax，所以 `$a_1 + b_1$` 這種含底線的式子有被轉成 `<em>` 的風險；程式碼區塊沒有語法上色。以上依原始碼推論，未實測。

> 「所以答案是：可以，但要我去改一個全域設定，而且數學式裡的底線可能會壞。那我還是自己在本機轉好 HTML 再貼比較穩。」

### 任務 3：出一份 5 題的隨堂小考

**3a. 純網頁路徑**

| 頁面 | 網址 | 觀察 |
| --- | --- | --- |
| 試卷管理（E3 自製） | `/local/courseextension/index.php?courseid=23571&scope=quiz` | 分頁：新增試卷、進行中、待批、已批、預告、暫存試卷 |
| 新增測驗卷 | `/course/modedit.php?add=quiz…` | 140 個可填欄位，初始顯示 7 個；10 個可收合區段。開始時間、截止時間各是「勾選啟用＋日／月／年／時／分 5 個下拉選單」，光排時間就要操作 12 個控制項 |
| 題庫 | `/question/edit.php?courseid=23571` | 上方是兩組篩選條件，「建立一新試題....」按鈕在第一個螢幕底部 |
| 試題類型選擇視窗 | 同頁 modal | 13 種以上題型的單選清單：選擇題、是非題、配合題、簡答題、數字題、申論題、全有或全無選擇題、三種拖放題、計算題、重新排序、填空題（克漏字）…；按「新增」才進編輯頁 |
| 編輯選擇題 | `/question/bank/editquestion/question.php?qtype=multichoice…` | 頁高 2928px（約 3.3 個螢幕）。30 個可見欄位、42 個可填欄位，**17 個富文字編輯器**（題目、試題回饋、5 個選項、5 個選項回饋、3 個合併回饋、2 個提示）。標示必填的只有名稱、題目、預設配分（已填 1）；另外至少要 2 個選項、其中一個成績設 100%，否則存檔時才報錯 |
| 編輯簡答題 | `qtype=shortanswer` | 21 個可見欄位。注意：Moodle 的「簡答題」是**自動比對字串**，答案要完全符合；老師說的「簡答」（人工改）在 E3 叫「申論題」 |
| 編輯申論題 | `qtype=essay` | 19 個可見欄位，有字數上下限、可否附檔、回應樣版、評分者訊息 |

把**一題選擇題放進一份新小考**，最少要經過：

1. 側欄「試卷管理」→ 頁面 1
2. 「新增試卷」→ 頁面 2，填名稱、勾選並設定開始與截止時間（12 個控制項）、存檔
3. 測驗頁 → 「試題」編輯頁 → 頁面 3、4
4. 「新增」→「一個新試題」→ 類型視窗 → 選擇題 → 新增 → 頁面 5
5. 填名稱、題目、4 個選項、把正確選項的成績下拉選成 100% → 儲存 → 回到頁面 4

**約 5 次換頁、20 次以上點擊、至少 10 個欄位**。之後每多一題選擇題，至少再 2 次換頁與 7 個欄位。5 題的小考大約 13 次換頁。第 3、4 步的測驗「試題」頁我們沒有實際看到，因為這門課沒有任何測驗，而建立測驗需要存檔；步驟依 Moodle 4.5 的流程推估。

> 「17 個富文字編輯器，就為了一個四選一。每個選項欄位都是一個完整的 TinyMCE，我按 Tab 要按多少下才到成績那個下拉選單？」

**3b. 匯入路徑**

匯入頁 `/question/bank/importquestions/import.php?courseid=23571` 提供的格式（單選，預設沒有選取）：

| 選項名稱（E3 原文）              | Moodle 格式代號  |
| -------------------------------- | ---------------- |
| 填空(克漏字)題                   | `multianswer`    |
| Aiken 格式                       | `aiken`          |
| Blackboard                       | `blackboard_six` |
| CSV format                       | `csv`            |
| Gift 格式                        | `gift`           |
| Missing word格式(克漏字、填空題) | `missingword`    |
| Moodle XML 格式                  | `xml`            |

匯出頁則提供 Aiken、CSV format、Gift、Moodle XML、XHTML。匯入頁的「一般」區段收合，裡面有目標類別（只有一個「ICT.20260316的預設」）、從檔案取得類別／情境、成績比對方式、遇錯是否停止。檔案用拖放區或「選擇一檔案…」（會開 Moodle 的檔案挑選器）。

用 GIFT 的路徑：

1. 在本機寫 `quiz3.gift`（5 題，含 `[markdown]` 或 `[html]` 標記、`$…$` 數學式、申論題用 `{}`）
2. 題庫維護 → 匯入 → 選「Gift 格式」→ 拖檔 → 匯入 → 確認頁「繼續」（2–3 次換頁）
3. 新增測驗卷（同 3a 第 2 步）
4. 測驗「試題」頁 →「新增」→「從題庫」→ 勾 5 題 → 加入（2 次換頁）

**大約 7 次換頁，題目本身 0 個網頁欄位**。省掉的是最痛的部分（17 個編輯器 × 5 題），但「建立測驗卷」那張 140 欄位的表單仍然躲不掉。

格式比較：

| 格式       | 適合黃老師嗎                                                                                                |
| ---------- | ----------------------------------------------------------------------------------------------------------- |
| GIFT       | 最適合。純文字、可手寫、可 diff；支援選擇、是非、簡答、數字、配合、申論；可在題目前加 `[markdown]` 指定格式 |
| Moodle XML | 最完整（圖片可 base64 內嵌、每個選項的回饋、提示、標籤），但不適合手寫，適合由工具產生                      |
| Aiken      | 只有單選題，沒有回饋，不能放申論題                                                                          |
| CSV format | E3 上看得到，但這是外掛格式，欄位規格要看該外掛的說明，不建議依賴                                           |

> 「GIFT 我五分鐘就能寫完五題。真正卡的是建立測驗卷那張表，還有開始時間那十個下拉選單。」

### 任務 4：批次匯入成績 CSV

E3 有兩個入口：

- **匯入 CSV** `/grade/import/csv/index.php?id=23571`：10 個欄位。檔案（.csv / .txt）、編碼（UTF-8、CP950、BIG5 等數十種）、分隔符號（Tab、逗號、冒號、分號）、詳細的量尺、預覽行數、強制匯入。
- **從試算表貼上** `/grade/import/direct/index.php?id=23571`：直接貼上試算表內容，6 個欄位。對黃老師這種會從 terminal 複製的人反而更快。

上傳後的對應步驟需要送出表單，研究帳號不能做，以下依 Moodle 4.5 原始碼：

1. 預覽前 N 行。
2. **辨識使用者**：選 CSV 的某一欄，對應到 `userid`（Moodle 內部 ID）、`username`（帳號）、`useridnumber`（ID 號碼）或 `useremail`（電子郵件）其中一種。
3. **成績項目對應**：每個 CSV 欄位選「忽略」、「新的成績項目」、某個既有成績項目，或某個項目的回饋。
4. 上傳成績。找不到的使用者會列出錯誤。

身分欄位的實際情況：

- 在 E3 網頁的成績管理頁上，「帳號」欄是 9 位數學號，所以 E3 自己的 CSV 匯入應該可以用學號對應 `username`。
- **API 拿不到學生的學號。** `mod_assign_list_participants`、`core_enrol_get_enrolled_users`、`core_user_get_course_user_profiles` 都只回傳姓名、email、Moodle 內部 ID。`core_user_get_users_by_field field=username` 查別人回傳空陣列，查自己才有結果；用 `email` 查別人則查得到。
- 這門課的學生 email 混用 `@nycu.edu.tw` 和外部信箱，所以 email 不能從學號推算。
- 用成績簿匯入會把該項目標成「已覆寫」，作業頁的評分表不會同步，學生在作業頁看不到評語。直接用 `mod_assign_save_grades` 寫入則會走作業本身，評語也會一起存。

**作業頁的相關功能**（`/mod/assign/view.php?id=218500&action=grading`）：「下載全部繳交的作業」和「以一個壓縮檔上傳多個回饋檔案」都有。「上傳評分工作表」沒出現，因為 E3 新作業預設沒有開「離線評分工作表」（`assignfeedback_offline_enabled` 預設未勾，期末報告也沒開）；回饋檔案、回饋評論、PDF 註記則預設開啟。

> 「所以 E3 自己可以用學號對，但第三方客戶端只能用 email 或內部 ID 對。那 EM3 要嘛先給我一個名單範本，要嘛幫我產生 E3 吃得下的 CSV。」

## 痛點（依嚴重度排序）

1. **出一題選擇題要 5 次換頁、17 個富文字編輯器。** 5 題小考約 13 次換頁。鍵盤使用者幾乎無法用 Tab 走完。
2. **沒有 Markdown。** 唯一的途徑是改全帳號的編輯器偏好，而且 Markdown 和 `$…$` 數學式有衝突風險。
3. **建立測驗卷的表單有 140 個欄位**，日期時間用 5 個下拉選單拼起來。即使題目用 GIFT 匯入，這一步還是躲不掉。
4. **用學號匯入成績這件事，E3 網頁做得到，第三方客戶端做不到**（API 不給學號）。
5. **成績簿匯入和作業評分是兩套。** 用 CSV 匯入成績簿，作業頁看不到分數與評語。
6. **E3 用詞與 Moodle 不同**：線上編輯文件＝page，教材＝folder，測驗卷／試卷＝quiz，「簡答題」是自動比對而不是人工改。老師查 Moodle 官方文件時對不起來。
7. **貼上程式碼不可靠**。要記得用「插入程式碼」或原始碼檢視，否則縮排與引號可能被改掉。
8. 左側抽屜在 1440 寬時會蓋住表單標籤，看不到欄位名稱。

## 需求

**Must**

- 從 autograder 產生的 CSV 批次寫入作業成績與評語，寫到作業本身（不是成績簿覆寫）。
- 匯入前預覽：誰對到了、誰沒對到、哪些分數超出滿分、哪些人已經有分數會被覆蓋。
- 題目可以用純文字（GIFT）撰寫，不用在網頁一題一題點。

**Should**

- Markdown（含程式碼區塊與 `$…$`）轉成 E3 能正確顯示的 HTML，一鍵複製後帶到 E3 的正確編輯頁。
- 公告也能用 Markdown 寫。
- 下載全部繳交作業，檔名能直接被腳本處理（含學號或固定 ID）。

**Could**

- 題目庫存在自己的 Git repo，EM3 讀 GIFT 檔產生預覽。
- 把小考的開始、截止時間用文字輸入（`10/22 10:10–10:30`），產生要貼進 E3 表單的值或提示。
- 鍵盤快捷鍵切換學生、輸入分數。

| Markdown 編輯              | 非常需要，但重點是「輸出 E3 能用的 HTML」，不是「EM3 裡多一個編輯器」                      | **成立，但要換形式**                                         |
| 新增不同的文件             | 他每週只放一頁說明和一兩個 PDF，主要痛在格式，不在上傳。資料夾上傳沒有 API                 | **弱**，交接即可                                             |
| 建立小考                   | 痛點最大的一項，但他要的是「用純文字出題」。GIFT 檔產生器是可行的；建立測驗卷本身仍要在 E3 | **成立，形式是 GIFT 產生＋交接**                             |
| 評分很重要、最常用         | 對他是成立的，但他的評分是批次的，不是逐份看。最重要的是 CSV 匯入                          | **成立**                                                     |
| 下載作業、改完再上傳回去   | 他下載是為了跑測試，「上傳回去」的是分數與評語 CSV，偶爾才有回饋檔                         | **部分成立**：下載＋批次回寫成績，比「上傳批改過的檔案」重要 |

## 「在 EM3 寫 Markdown → 交給 E3」的設計評估

API 沒有建立、編輯模組的功能，所以所有「發布教材」的設計都要靠交接。以下依可行性排列：

| 設計 | 做法 | 可行性 | 評語 |
| --- | --- | --- | --- |
| A. Markdown 公告直接發布 | 本地把 Markdown 轉成 HTML（程式碼區塊轉成 `<pre><code>`，`$…$` 原樣保留給 E3 的 MathJax），用 `mod_forum_add_discussion` 發到公告 | **可以直接寫入** | 唯一能真正完成的 Markdown 寫入路徑。適合「本週說明」這類內容 |
| B. Markdown → 複製 HTML → 開 E3 編輯頁 | EM3 轉成 HTML、複製到剪貼簿，開 `/course/modedit.php?add=page&course=…&section=…`（或既有頁面的 `update=`），提示「按原始碼按鈕、貼上、存檔」 | 交接 | 老實、可靠。每次約 4 次點擊。風險是 TinyMCE 會清理部分 HTML，要測哪些標籤會被保留 |
| C. 下載 `.html` 檔，再上傳成「檔案」資源 | 產生自帶樣式的 HTML 檔，老師在 E3 新增檔案資源 | 交接 | 樣式可以完全掌控，但 E3 的 MathJax 不會套用在檔案上，要把數學式先轉成 SVG；而且 E3 會強制下載 |
| D. 要求老師切換成「純文字區域＋Markdown」 | 在 EM3 說明怎麼設定 | 不需寫程式 | 影響全帳號，數學式有底線問題，不建議作為主要方案 |
| E. 在 EM3 做完整的教材編輯器並同步到 E3 | — | **不可行** | 沒有 API |

建議以 A＋B 為主：同一個 Markdown 編輯面板，下方兩個按鈕「發布為公告」（直接寫入）和「複製 HTML 並開啟 E3」（交接）。轉換結果要在 EM3 裡預覽，而且預覽要用與 E3 相同的 MathJax 規則（`$…$`、`\(…\)`、`$$…$$`）。

## 功能提案

依黃老師的優先順序排列。

| 優先 | 功能 | 說明 | API 可行性 |
| --- | --- | --- | --- |
| 1 | **成績 CSV 匯入到作業** | 選一份作業 → 拖 CSV → 選身分欄與分數欄、評語欄 → 預覽（對到、沒對到、超過滿分、會覆蓋既有分數）→ 寫入。另外提供「下載名單範本」：EM3 匯出 `userid,姓名,email,分數,評語`，老師或 autograder 只要把分數填進去，避開學號對不到的問題 | `mod_assign_save_grades`，評語用 `assignfeedbackcomments_editor`（可用 Markdown 轉 HTML）。**身分只能用 Moodle 內部 ID 或 email**，API 拿不到學號 |
| 2 | **產生 E3 成績簿 CSV** | 老師的 CSV 只有學號時，EM3 不改資料，只產生 E3 匯入頁吃得下的 CSV（UTF-8、逗號分隔），並開啟 `/grade/import/csv/index.php?id=…`，附上「身分欄選『帳號』」的提示 | 交接。由 E3 自己用 `username` 對應學號。要提醒這會覆寫成績簿，作業頁不會同步 |
| 3 | **GIFT 小考工作台** | 左邊寫 GIFT，右邊即時預覽每一題（MathJax、程式碼區塊），驗證每題至少一個正確答案、申論題格式；下載 `.gift` 檔並開啟題庫匯入頁。再提供「下一步：建立測驗卷 → 從題庫加入」的步驟清單與連結 | 交接。題目與測驗都沒有建立 API。也可以輸出 Moodle XML，處理圖片內嵌 |
| 4 | **Markdown 公告** | 見上面設計 A | `mod_forum_add_discussion` 可直接寫入 |
| 5 | **Markdown → E3 頁面交接** | 見上面設計 B，包含開啟 `add=page` 或 `update=<cmid>` 的正確網址 | 交接 |
| 6 | **下載全部繳交** | 一鍵下載某份作業的所有繳交，資料夾名用 `userid_email`，並附一份 `manifest.csv`（userid、email、繳交時間、是否遲交）讓 autograder 直接讀 | 讀取 API 可行（`mod_assign_get_submissions` 取得檔案網址，加 token 下載）。學號同樣拿不到 |
| 7 | **批次回饋檔** | autograder 產生的每人一份報告，依 userid 對應上傳成回饋檔 | `/webservice/upload.php` 取得 draft itemid，再用 `mod_assign_save_grade` 的 `files_filemanager`。可行但每人一次請求 |
| 8 | **鍵盤評分模式** | 逐份檢視時 `j` / `k` 切換學生、數字鍵輸入分數、`Enter` 存檔 | `mod_assign_save_grade` |

不建議做的：在 EM3 裡做「新增教材」、「新增資料夾」、「新增測驗卷」的表單。API 做不到，做出來的半成品會讓老師以為已經發布了。

## 研究限制

- 人物和引言都是模擬的。
- 沒有存檔，所以以下都沒有實測：Markdown 格式的實際渲染、TinyMCE 貼上程式碼後的清理、GIFT 匯入的實際結果、CSV 匯入的對應頁畫面、測驗卷的「試題」編輯頁。這些都依 Moodle 4.5 原始碼推論。
- TinyMCE 在唯讀瀏覽器裡無法完整載入，編輯器的工具列外觀沒有看到，只確認了設定裡的外掛清單。
- 我們用了兩次 `core_user_get_users_by_field`（分別以一位學生的學號和 email 查詢），只為了確認 API 能不能用學號對應；查詢結果沒有寫進報告。
