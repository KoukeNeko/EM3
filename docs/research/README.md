## E3 實際上怎麼被使用

- **課程頁幾乎沒有結構。** 34 門學期課裡有 27 門只有一個「一般」區段，沒有週次，新東西永遠在最下面。
- **教材 = 資料夾。** E3 把 `folder` 改名成「教材」。大部分資料夾只放 1–3 個檔案，有些是空的，用 intro 放 Google Drive 連結或影片。檔案以 PDF（約一半）、PPTX、MP4 為主。
- **作業 = 檔案上傳。** 94 份作業幾乎都只開檔案繳交，沒有開草稿。截止時間集中在 23:59，但有一部分設在 `00:00`，在 E3 上顯示成隔天的「AM 12:00」，很容易看錯。
- **公告 = 每門課一個 news forum。** 一學期中位數約 5 則，沒有未讀追蹤（`istracked=false`），所以客戶端要自己記錄已讀。
- **幾乎沒有其他活動。** 只有少量 quiz、`supervideo`（E3 自製影片模組）和 url；沒有 LTI、H5P、choice、feedback。
- **上課時間不在 E3 裡。** 只在課程綱要系統（timetable.nycu.edu.tw）上，格式如 `T34R7-EC022`。

## 學生的主要痛點（5 份訪談的交集）

1. **沒有「我這週要交什麼」的地方。** 首頁「未來事件」在 3–5 個螢幕高度之下，沒有課名，也不顯示自己交了沒有；逾期的只出現在通知鈴裡。
2. **時間格式混亂。** 至少 8 種格式，12/24 小時制混用，`00:00` 截止被讀成隔天。公告只寫日期，要心算是星期幾。
3. **用詞重疊。** 焦點綜覽／我的課程／當期課程／歷年課程；公告／公告列表／討論區；課程綱要／大綱列表／課程大綱；試卷＝測驗。
4. **繳交流程太長。** 要 4–7 步，檔案挑選器裡有維基圖庫、Google、伺服器檔案、作者欄、8 種 CC 授權；按鈕叫「儲存更改」而不是「繳交」；還沒交時麵包屑就寫「修改已繳交的作業」。
5. **PDF 一律強制下載。** 課程頁的連結帶 `forcedownload=1`，只有「教材列表」那條路徑可以在瀏覽器預覽。
6. **課程列表沒有學期概念。** 依名稱排序時，本學期的課在第 3 頁；微學分、線上課程、以人名命名的課混在一起；課名被截斷。
7. **慢。** 一般頁面 2–6 秒，首頁和成績頁 7–9 秒，上一頁要整頁重載。
8. **手機版與無障礙。** 表格溢出、沒有主選單、沒有深色模式、部分對比 1.8:1、鍵盤 focus 看不到。

## 研究過程對帳號造成的副作用

研究全程不繳交、不上傳、不發文，但以下兩件事寫入了帳號偏好，都已經改回原值：

- 交換生 agent 點了 E3 頁首的「EN」，結果把帳號語言存成英文，之後改回 `zh_tw`。我用 `core_user_get_users_by_field` 確認過目前是 `zh_tw`。
- 大四 agent 切換「我的課程」的分組下拉選單時，送出了偏好設定的 POST，最後已改回原本的「全部」。

另外，瀏覽課程和作業頁面會在 E3 留下一般的「已檢視」紀錄（Moodle log），這是瀏覽本身就會產生的。
